# Yuksalish Workspace

Монорепозиторий самодостаточной корпоративной платформы Yuksalish. Главный продукт — единое Windows-приложение для общения, задач и управляемых процессов согласования. Hisobot переносится позже как один из модулей платформы.

## Живая desktop-альфа

Текущая версия — **0.16.0**: широкие формы проектов, поездок и оплат в стиле Yuksalish — разделы полей, живая сводка, стадии и закреплённая панель действий. Добавлены поиск участников поездки, пересчёт остатка бюджета, защита от повторной отправки и сохранение ввода при ошибке. [Дизайн и проверка форм](docs/design/record-composers.md). Правила согласования и сервер не изменены.

В 0.15.1 логотип бокового меню поднят на 5 px. [Диагностика повторяющихся сеансов](docs/architecture/session-list-diagnosis.md): отдельные входы с одинаковым названием; существующие пользовательские сеансы не изменены.

Desktop alpha **0.15.0** — единая переработка интерфейса по брендбуку: встроенный Gilroy (четыре начертания), фирменные #0091A8 / #293A55, светлая навигация, согласованные панели, формы и типографика во всех рабочих разделах. Добавлены быстрый переход по разделам (Ctrl+K), поиск задач в списке/Kanban и поиск сотрудников, клавиатурное управление календарём и фокусом модальных окон. Оригинальные логотипы, цвета стадий Bitrix, пересчёт сумм, закрепления и архив чатов сохранены. API остаётся 0.14.0, миграция `0017_personal_organization`. Подробнее: [дизайн-система и проверка](docs/design/workspace-design-system.md).

Desktop alpha 0.14.1 выравнивает видимый край логотипа на странице входа по тексту при любой ширине окна. Дублирующий логотип верхней панели убран: там снова только живой статус подключения, а фирменный знак остаётся в левом меню. PNG не изменялись. Сервер остаётся на API 0.14.0, новых миграций нет. Подробнее: [фирменное оформление](docs/architecture/company-branding.md).

Desktop/API alpha 0.14.0 добавляет личные закрепления чатов с drag&drop, архив без удаления переписки и редактор порядка всех кнопок левого меню через карандаш. Настройки сохраняются в PostgreSQL отдельно для каждого сотрудника, синхронизируются между устройствами и защищены от конфликтующих изменений. Требуется миграция `0017_personal_organization` и API 0.14.0; локальный сервер обновлён. Подробнее: [личная организация](docs/architecture/personal-organization.md).

Desktop alpha 0.13.6 добавила оригинальный логотип компании в интерфейс (размещение уточнено в 0.14.1). Удалён указанный пользователем поясняющий абзац о доступе и сессиях; сама защита входа не изменялась. Логотипы встроены в сборку, сохраняют пропорции и адаптируются к размеру окна. Подробнее: [фирменное оформление](docs/architecture/company-branding.md).

Desktop alpha 0.13.5 добавляет плавный пересчёт сумм колонок оплат за 260 мс и единые контекстные акценты/glow в основных разделах. Точные суммы, копейки и валюты сохраняются; анимация не перерисовывает всю доску и учитывает системное уменьшение движения. Свечение ограничено состояниями выбора, фокуса, наведения и кратким обновлением суммы. Подробнее: [анимация и цвета](docs/architecture/ui-motion-and-colors.md). Данные, API и схема БД не изменялись.

Desktop alpha 0.13.4 добавляет Канбан согласования поездок по аналогии с оплатами: пять стадий с точными цветами Bitrix, вертикальные очереди карточек, защищённый drag&drop, поиск и переключение на список. Возврат и отклонение требуют причины; исправление, повторная отправка и история сохранены. В поездках пока нет поля суммы: непустая колонка показывает «Не задана», пустая — `0 UZS`. Цвета и суммы оплат из 0.13.3, исправление белого экрана из 0.13.2 и улучшения сообщений из 0.13.1 сохранены. API и схема БД совместимы с 0.12.0, новой миграции не требуется. Подробнее: [поездки](docs/architecture/trip-approvals.md), [заявки на оплату](docs/architecture/payment-workflows.md), [устойчивость desktop](docs/architecture/desktop-resilience.md).

- корпоративный мессенджер: любой сотрудник создаёт личный диалог или закрытую группу, добавляет сотрудников Workspace и становится владельцем своей группы;

- ответы на сообщения, адресные упоминания с уведомлениями, редактирование и удаление своих сообщений в течение 24 часов с сохранением неизменяемой истории;
- поиск, серверные отметки прочтения, отправка, вложения и действие «создать задачу из сообщения»; подробные правила описаны в [спецификации мессенджера](docs/architecture/messenger-groups.md);

- персональный центр уведомлений с очередями «требует действия», «не прочитано» и «все», поиском, отметками прочтения и переходом прямо в чат, задачу, заявку, командировку или событие;
- идемпотентные серверные напоминания о задачах и событиях на ближайшие 24 часа, отдельные настройки категорий и нативные уведомления Windows, когда приложение свёрнуто или находится в фоне;
- задачи с редактируемой карточкой, сроком и приоритетом, участниками, рабочим чек-листом, комментариями, файлами и исходным сообщением;
- список и Kanban с переносом между статусами, блокирующие и информационные зависимости, а также включаемые ежедневные, еженедельные и ежемесячные циклы;
- доска проектов со стадиями `Начало → Подготовка → Согласование → Успех/Провал`, карточкой руководителя, сроками, валютой, бюджетом, расходом, остатком и журналом переходов;
- командировки с целью, направлением, периодом и сотрудниками, возвратным циклом и маршрутом `Запуск → Руководитель → Кадровая служба → Утверждено/Отклонено`;
- полная карточка заявки на оплату: проект, счета, тип и основание перевода, приоритет, срок, поездка, сотрудники, ответственный и два вида документов;
- горизонтальная Fluent-доска всех стадий с вертикальными очередями заявок, поиском, фильтрами и переносом карточки на следующий разрешённый этап;
- drag&drop не изменяет стадию напрямую: он вызывает обычное защищённое действие API, поэтому должностные права, возвраты и параллельные решения остаются обязательными;

- создание, стадии и вывод из доработки назначаются стабильным должностям; названия должностей принимаются только на латинице;
- общие вложения до 25 МБ с хранением содержимого в MinIO, метаданных и SHA-256 в PostgreSQL и серверной проверкой доступа;
- визуальный редактор версионируемого графа согласования без изменения кода;
- вход по логину и Argon2id-паролю, приглашения, TOTP, восстановление доступа и отзыв сессий;
- роли сотрудника, руководителя и администратора, проверяемые сервером.

- вкладку «Сотрудники» с раздельным назначением роли доступа и редактируемой должности;

CRM сохраняется в левом меню только как элемент подтверждённой навигации. Пакет BP-9 сознательно пропущен и не входит в текущий roadmap или первый релиз.

Данные хранятся в PostgreSQL и доступны через FastAPI gateway. Access-токен живёт 15 минут, отдельная refresh-сессия привязана к устройству и может быть завершена пользователем. Коды приглашения и восстановления одноразовые; при восстановлении пароля старые сессии отзываются.

Тестовый Windows installer собирается командой:

```powershell
pnpm --filter @yuksalish/desktop dist:win
```

## Структура

- `apps/api` — FastAPI API и Alembic migrations;
- `apps/desktop` — защищённая Electron/React/TypeScript оболочка;
- `apps/worker` — фоновые задания;
- `apps/scheduler` — планировщик;
- `modules/hisobot/importer` — проверяемый контракт импорта старого Hisobot;
- `packages` — общие TypeScript-контракты и локализация;
- `infrastructure` — Docker Compose и gateway;
- `tests` — Python unit/integration tests;
- `docs` — архитектурные решения и runbooks.

Production-снимки, SQLite, PDF, EXE, журналы и `.env` намеренно не входят в Git.

## Быстрый старт

```powershell
Copy-Item .env.example .env
.\scripts\bootstrap.ps1
docker compose --env-file .env -f infrastructure\compose.yaml up -d --build
.\scripts\check.ps1
```

API через gateway: `http://127.0.0.1:8080/api/v1/health/live`.

`check.ps1` требует запущенный Docker Desktop. Скрипт создаёт отдельную базу `yuksalish_test`, применяет к ней миграции и пересоздаёт только эту тестовую базу; рабочая база `yuksalish` не очищается.

Для staging и production используются отдельные локальные файлы секретов. Порядок их
подготовки и обязательная проверка описаны в `docs/operations/environments.md`; шаблоны
`.env.staging.example` и `.env.production.example` нельзя запускать без замены заглушек.

Desktop в dev-режиме:

```powershell
pnpm dev:desktop
```

Desktop показывает экран входа. В локальной alpha доступны `aziza`, `baxtiyor`, `dilshod`, `malika` с паролем из `YUKSALISH_DEMO_PASSWORD`; у Малики роль администратора. Gateway и PostgreSQL должны оставаться запущенными.

В production демонстрационные пользователи отключены. Первый администратор создаётся один раз в пустой базе с интерактивным вводом пароля:

```powershell
docker compose exec api yuksalish-bootstrap-admin `
  --username admin --full-name "Имя администратора"
```

Следующих сотрудников администратор приглашает из панели «Аккаунт и безопасность» и сразу выбирает им должность из справочника. Роль доступа и должность намеренно не объединяются.

## Импорт Hisobot

Инспекция всегда открывает SQLite только для чтения:

```powershell
.\.venv\Scripts\python.exe -m hisobot_import inspect `
  --database "Hisobot AI\data\hisobot.sqlite3" `
  --archive "Hisobot AI\data\archive"
```

Пишущий импорт требует точного fingerprint, применённых Alembic-миграций и настроек
PostgreSQL/MinIO из локального `.env`:

```powershell
.\.venv\Scripts\python.exe -m hisobot_import apply `
  --database "Hisobot AI\data\hisobot.sqlite3" `
  --archive "Hisobot AI\data\archive" `
  --confirm-fingerprint "<fingerprint из inspect>" `
  --upload-files
```

Повторный запуск того же snapshot и mapping возвращает существующий подтверждённый import
run и не создаёт строки или файлы повторно.

Проверяемые результаты полной двухпроходной Docker-репетиции сохранены в
`docs/import/hisobot-rehearsal-2026-09-02.md`.

## Инженерные правила

- основная ветка — `main`;
- рабочие ветки — `feature/*` и `fix/*`;
- изменения проходят lint, typecheck, tests, build и проверку секретов;
- секреты задаются только на целевой машине или через защищённый CI secret store;
- миграции данных выполняются повторяемо и никогда не изменяют исходный SQLite.
