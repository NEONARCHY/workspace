# Новое проектное пространство

«Проекты» и «Проектные заявки» — самостоятельные модули. Старые «Список проектов» и «Заявки на оплату» скрыты из меню и поиска разделов, но их записи, маршруты, API и прямые переходы из прежних уведомлений не удалены и не переносятся автоматически. Новые проектные задачи также не становятся записями общего модуля «Задачи».

## Проект и работы

Проект хранит руководителя, других ответственных, бюджет в одной валюте, даты, описание, открытый/закрытый доступ и активный/завершённый статус. Закрытый проект доступен руководителю, создателю, ответственным, согласующим, исполнителям работ, участникам заявок и администраторам. Создавать проект может пользователь с правом модуля и ролью руководителя или администратора; изменять его — назначенный руководитель либо администратор.

Внутри проекта хранятся отдельные задачи и мероприятия с исполнителями, плановым бюджетом, началом, сроком и состоянием. Обзор показывает согласованную сумму, остаток бюджета, план активных работ, просрочки и ближайшие 20 дней. Плановый бюджет работ — прогноз, а не фактический расход. Итоговая сумма согласованных заявок не может превышать бюджет проекта; уменьшить бюджет ниже уже согласованной суммы нельзя. Для первой версии суммы целочисленные в выбранной валюте, без конвертации валют и бухгалтерского начисления.

Руководитель публикует мероприятие в общем календаре явным действием. Повторное действие не создаёт дубль. Редактирование опубликованной встречи в календаре обновляет её название, описание и время в проекте; отмена в календаре отменяет проектное мероприятие. После публикации время и название меняют в календаре. Проектное мероприятие нельзя заново открыть после отмены опубликованной встречи. Участники календаря и исполнители проектной работы после публикации живут по разным правилам: изменение приглашённых в календаре не меняет исполнителей работы.

## Проектные заявки

К одной задаче или мероприятию можно создать несколько независимых денежных заявок. Создатель — руководитель проекта, ответственный или исполнитель работы с правом модуля. Маршрут — упорядоченный список сотрудников из проекта, скопированный в каждую новую заявку; последующее изменение маршрута не меняет запущенные заявки. Решение принимает только текущий согласующий. Отказ требует комментария. После последнего согласования заявка считается одобренной и учитывается в бюджете. Несколько параллельных заявок могут ожидать решения; проверка лимита происходит при окончательном одобрении внутри транзакции с блокировкой проекта. История решений сохраняется. Галочка «все согласования пройдены» ставится только если пользователю доступны все заявки этой работы и каждая одобрена.

## Сроки, права и выпуск

Планировщик раз в цикл ищет активные работы со сроком в пределах 20 дней и посылает руководителю и исполнителям уведомления на порогах 20, 7 и 1 день. Ключ уведомления включает работу, её текущий срок и порог, поэтому повторный запуск не создаёт дубль. Изменение срока формирует новый набор уведомлений. Просроченные и завершённые работы новых напоминаний не получают.

Сервер отдельно проверяет право модуля и доступ к конкретному проекту/заявке; видимость кнопки не служит защитой. Существующие персональные порядки меню сохраняются при добавлении новых ключей; старые разделы только скрываются. Для выпуска требуется миграция `0056_project_hub` после `0055_ai_referent_preflight`, запуск API и scheduler, затем сборка и установка нового desktop. Перед обновлением сервера следует сделать резервную копию БД по обычному runbook. Миграция создаёт новые таблицы и не изменяет старые проектные/платёжные записи.
