# Новое проектное пространство

«Проекты» и «Проектные заявки» — самостоятельные модули. Старые «Список проектов» и «Заявки на оплату» скрыты из меню и поиска разделов, но их записи, маршруты, API и прямые переходы из прежних уведомлений не удалены и не переносятся автоматически. Новые проектные задачи также не становятся записями общего модуля «Задачи».

## Проект и работы

Проект хранит руководителя, других ответственных, бюджет в одной валюте, даты, описание, открытый/закрытый доступ и активный/завершённый статус. Закрытый проект доступен руководителю, создателю, ответственным, согласующим, исполнителям работ, участникам заявок и администраторам. Создавать проект может пользователь с правом модуля и ролью руководителя или администратора; изменять его — назначенный руководитель либо администратор.

Внутри проекта сначала создаются направления (например, «Проведение форума»). Каждая задача и мероприятие принадлежит одному направлению и хранит исполнителей, плановый бюджет, начало, срок и состояние. Направление можно переименовать без изменения истории работ; в новом интерфейсе работы нельзя создать вне направления. Ради совместимости старый desktop без поля направления помещает новую работу в «Ранее добавленные работы», а при редактировании сохраняет её прежнее направление. Миграция `0057_project_workstreams` относит существующие работы к тому же направлению, сохраняя их идентификаторы, заявки и события календаря. Обзор показывает согласованную сумму, остаток бюджета, план активных работ, просрочки и ближайшие 20 дней. Плановый бюджет работ — прогноз, а не фактический расход. Итоговая сумма согласованных заявок не может превышать бюджет проекта; уменьшить бюджет ниже уже согласованной суммы нельзя. Для первой версии суммы целочисленные в выбранной валюте, без конвертации валют и бухгалтерского начисления.

Руководитель публикует мероприятие в общем календаре явным действием. Повторное действие не создаёт дубль. Редактирование опубликованной встречи в календаре обновляет её название, описание и время в проекте; отмена в календаре отменяет проектное мероприятие. После публикации время и название меняют в календаре. Проектное мероприятие нельзя заново открыть после отмены опубликованной встречи. Участники календаря и исполнители проектной работы после публикации живут по разным правилам: изменение приглашённых в календаре не меняет исполнителей работы.

## Проектные заявки

К одной задаче или мероприятию можно создать несколько независимых денежных заявок. Создатель — руководитель проекта, ответственный или исполнитель работы с правом модуля. Новая форма требует крайнего срока согласования с часовым поясом; API временно допускает отсутствие срока ради совместимости с уже установленными старыми клиентами. У ранее созданных заявок срок остаётся пустым. Маршрут — упорядоченный список сотрудников из проекта, скопированный в каждую новую заявку; последующее изменение маршрута не меняет запущенные заявки. Канбан группирует заявки по состояниям «На согласовании», «Согласовано», «Отклонено», а карточка показывает текущего согласующего, срок, файлы и историю решений. Решение принимает только текущий согласующий. Отказ требует комментария. После последнего согласования заявка считается одобренной и учитывается в бюджете. Несколько параллельных заявок могут ожидать решения; проверка лимита происходит при окончательном одобрении внутри транзакции с блокировкой проекта. История решений сохраняется. Галочка «все согласования пройдены» ставится только если пользователю доступны все заявки этой работы и каждая одобрена.

Создатель может прикреплять файлы к заявке, пока она ожидает решения. Участники маршрута, руководитель проекта и администраторы могут их скачать; посторонние не имеют доступа даже по прямой ссылке. Файл загружается после создания заявки через её карточку в модуле «Проектные заявки». Для выпуска MinIO должен оставаться доступным. Срок обозначает ожидание согласования, но сам по себе не отклоняет заявку автоматически.

## Сроки, права и выпуск

Планировщик раз в цикл ищет активные работы со сроком в пределах 20 дней и посылает руководителю и исполнителям уведомления на порогах 20, 7 и 1 день. Ключ уведомления включает работу, её текущий срок и порог, поэтому повторный запуск не создаёт дубль. Изменение срока формирует новый набор уведомлений. Просроченные и завершённые работы новых напоминаний не получают.

Сервер отдельно проверяет право модуля и доступ к конкретному проекту/заявке; видимость кнопки не служит защитой. Существующие персональные порядки меню сохраняются при добавлении новых ключей; старые разделы только скрываются. Для этого пакета требуются миграции `0057_project_workstreams` и `0057_hisobot_live_bridge` (обе после `0056_project_hub`), объединённые пустой ревизией `0058_project_hisobot_merge`, затем запуск API и scheduler, сборка и установка нового desktop. Команда `alembic upgrade head` применяет отсутствующую ветку и фиксирует единую ревизию независимо от того, какая из миграций 0057 уже применена. Перед обновлением сервера следует сделать резервную копию БД и MinIO по обычному runbook и проверить переход на копии рабочей БД. Проектная миграция добавляет направление, срок заявок и новый тип вложения, не меняя старые проектные/платёжные записи.
