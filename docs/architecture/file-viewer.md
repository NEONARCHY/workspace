# Встроенный просмотр вложений

Общий FileViewer открывается из стандартных вложений мессенджера, задач,
заявок и сохранённых документов AI Referent. Чтение не изменяет оригинал;
скачивание остаётся отдельным действием в просмотрщике. Входящие письма ЭДО используют
тот же интерфейс через ExternalFileViewer и собственные защищённые маршруты, не
подменяя идентификаторы общих вложений. Подробнее: [ЭДО](edo-incoming.md).
Документы импорта проектов и подписанные пакеты референта сохраняют прежние
собственные действия: это не вложения общего хранилища.

## Форматы и UX

В форме AI Referent выбранное, ещё не сохранённое письмо и приложения открываются
по названию/иконке через LocalFileViewer. PDF, изображения и медиа читаются непосредственно
из выбранного File. Для Office POST `/ai-referent/file-preview` требует сессию и право
просмотра модуля, ограничивает вход 25 МиБ и параллельность двумя запросами, использует
тот же защищённый парсер. Маршрут не записывает письмо, объект в хранилище, задание роботу
или результат проверки подписи. Закрытие отменяет запрос и освобождает preview URL.
Отдельная существующая проверка документа роботом сохраняет прежнее поведение.

- DOC/DOCX: новый клиент запрашивает `render=true` и получает PDF-страницы,
  построенные локальным LibreOffice Writer. Поля, таблицы, рисунки и разрывы
  страниц обрабатывает офисный движок, а не HTML-вёрстка. PDF.js сохраняет свои
  масштаб, переход между страницами и доступный текстовый режим. Скачивание
  отдаёт исходный Word, не PDF. При `render=false` старый DOCX text/table JSON
  остаётся совместимым с прежними клиентами. DOC в текстовом режиме не поддерживается.
  Системные шрифты Carlito, Caladea, Liberation, DejaVu и Noto заменяют отсутствующие
  гарнитуры; побайтовое/пиксельное совпадение с Microsoft Word не обещается.
- XLSX: имена листов, страницы по 200 строк, до 80 колонок, закреплённые
  заголовки и номера строк. Поиск относится к загруженной странице, не всей книге.
  Читаются сохранённые результаты формул; если результата нет, показывается
  формула как текст. Формулы не пересчитываются.
- PDF: отдельный lazy chunk PDF.js 5.5.207 и локальный worker, одна страница
  на canvas, предыдущая/следующая страница, масштаб и доступный текстовый режим.
  Bitmap ограничен 8 млн пикселей и 8192 px по стороне; чрезмерные размеры
  страницы отклоняются. Прежняя задача отрисовки отменяется и ожидается
  перед использованием того же canvas. Документ/worker уничтожаются при закрытии.
  Скрипты и интерактивные PDF-действия не запускаются: используется только
  API отрисовки и извлечения текста, `isEvalSupported: false`.
  Nginx отдаёт module-worker `.mjs` с JavaScript MIME, сохраняя nosniff и CSP.
- Фото: общий полноэкранный `ImageLightbox` на весь viewport, с тёмным полотном
  в обеих темах. Подпись, автор и дата доступны отдельно от фото. Ctrl/Command +
  колесо увеличивает фото около курсора (1–8× относительно вписанного размера),
  обычное колесо и стрелки листают фото. Есть поворот, сброс масштаба, перетаскивание
  увеличенного фото с ограничением краёв и сенсорное горизонтальное листание.
  SVG отображается только через img, не как HTML.

## Полноэкранная галерея — 15 октября 2026

`workspaceImageGallery` собирает изображения только из уже разрешённого bootstrap.
В мессенджере — все неудалённые сообщения **того же чата**, от любых авторов,
в порядке времени сообщения и вложений. После альбома доступны более ранние/поздние
фото переписки; переход не зацикливается на границах. Порог видимости истории и
состав доступных чатов по-прежнему определяет API; новых запросов к чужой истории нет.
Текущий bootstrap возвращает всю доступную историю без пагинации. Если в будущем
появится серверная пагинация, галерее понадобится отдельная защищённая подгрузка.
В остальных Workspace-разделах область ограничена одним ownerType/ownerId;
во входящих ЭДО — одним письмом, в несохранённой форме Referent — выбранными файлами.
Служебная подпись «Файл» скрыта, настоящий текст сообщения сохранён как plain text.

ПКМ или Shift+F10 открывает общий контекстный слой: копирование пикселей PNG в
Clipboard API, скачивание оригинала, поворот, «Все фотографии». Для сообщений
доступны переход к исходной строке и существующий ForwardDialog с явным выбором
чата; просмотр не отправляет сообщения автоматически. Копирование зависит от
поддержки/разрешения браузера и ограничено 32 млн пикселей; ошибка видима,
скачивание остаётся доступным. «Сохранить как…» использует обычный download браузера,
поэтому показ системного диалога определяется настройками браузера.

Фотографии/миниатюры загружаются через прежние авторизованные маршруты. Закрытие
и смена снимка отменяют запрос и освобождают object URL; устаревший ответ не
показывается вместо выбранного фото. Сетка миниатюр грузится по IntersectionObserver.
Escape сначала закрывает меню/сетку, затем просмотрщик; Fluent сохраняет focus trap
и возврат к источнику. Это полноэкранная область приложения, не принудительное
скрытие интерфейса браузера через Fullscreen API. Office/PDF/video/audio не меняются.
- Видео: нативный HTML5 player, без autoplay; аудио использует существующий
  плеер Workspace с громкостью и обложкой MP3. Неподдерживаемый codec показывает
  ошибку с сохранённой возможностью скачать оригинал. При закрытии аудио/видео
  явно приостанавливаются, src удаляется и media element очищается через load.
- XLS и неизвестные типы скачиваются, без обещания встроенного чтения.

Просмотрщик использует WorkspaceDialog, Fluent, Inter и существующие токены.
Esc, focus restoration, reduced motion и forced colors сохраняются. Фото в
мессенджере сохраняют превью: оно загружается только в видимой области,
отменяется и освобождается при уходе за viewport. Остальные файлы не загружаются
всем списком. Голосовые сообщения продолжают использовать прежний voice player.

## API и безопасность

`GET /api/v1/attachments/{id}/preview?sheet=0&offset=0` возвращает типизированное
OfficeFilePreview. Общий helper загрузки проверяет get_attachment и право view
соответствующего модуля до обращения к storage, как обычное скачивание.
Оба ответа используют `Cache-Control: private, no-store`; новые права не выдаются.
При `render=true` для DOC/DOCX этот же маршрут возвращает `application/pdf`.
Флаг также поддерживают собственные preview-маршруты ЭДО, приложения к поездке
и несохранённого файла AI Referent; их проверки доступа и read-scope не обходятся.
Для XLSX ответ остаётся JSON. Клиент выбирает обработчик по Content-Type и
сохраняет существующие timeout/abort и возможность скачать оригинал после ошибки.

## Изолированная конвертация Word

`office-preview` — отдельный непривилегированный контейнер без сети, портов,
секретов, БД или доступа к исходникам Workspace. Только API монтирует его
private Unix-сокет read-only. Корневая ФС read-only, capabilities удалены;
`/tmp` — ограниченный tmpfs без exec. Лимиты: 768 МиБ RAM, 1 CPU, 128 процессов,
192 МиБ временных файлов. Один файл обрабатывается одновременно; занятый движок
возвращает 503, не сообщает ложный успех. Вход ограничен 25 МиБ, PDF — 40 МиБ.
Для каждого запроса создаётся новый профиль Writer с MacroSecurityLevel=3 и без
доверенных расположений. Процессная группа останавливается через 35 секунд;
временный каталог удаляется после выполнения. Конвертер не сохраняет историю
или долговременный preview-кэш. Пакеты движка необходимо регулярно обновлять.

API проверяет подпись DOC/OLE либо RTF и существующие лимиты/запреты Office ZIP
для DOCX до IPC. Повреждённые, защищённые или неподдерживаемые файлы дают ошибку;
оригиналы не перезаписываются и не отправляются внешним сервисам. Изоляция
уменьшает последствия уязвимостей парсера, но не является полной security-сертификацией.

Параметры движка: [headless/convert-to](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html),
[уровень безопасности макросов](https://help.libreoffice.org/latest/en-US/text/shared/optionen/macrosecurity_sl.html).

В Compose сокет задаётся через `YUKSALISH_OFFICE_PREVIEW_SOCKET`; вне Compose
по умолчанию пуст и новый Word preview возвращает понятную 503. Не открывайте
конвертер в LAN/Internet и не подключайте к нему backend/egress-сети.

Существующие проверки Office ZIP ограничивают размер, число записей и заполненных
ячеек; макросы, зашифрованные архивы и внешние ссылки Excel отклоняются. XML
читает defusedxml, содержимое показывается React-текстом, без HTML-injection.
Word XML дополнительно ограничен 4 МБ; вывод — 2000 блоков и 350000 символов.
Для больших/обрезанных документов интерфейс явно предлагает оригинал.
Два параллельных чтения/разбора на процесс API ограничиваются semaphore;
разбор выполняется в thread, не блокирует event loop. Постоянного preview-кэша нет.

Закрытие или смена страницы отменяет клиентский запрос. Общий boundedRequest
сохраняет abort/timeout до чтения тела ответа, а не только до получения заголовков;
HTTP-ошибка не запускает failover. Неактуальные ответы не обновляют интерфейс,
object URLs освобождаются. Файлы не отправляются Microsoft/Google и другим сервисам.

## Проверка и выпуск

FileViewer.test, workspace-api.test, AttachmentPanel.test покрывают классификацию,
безопасный текст, таблицы, поиск, страницы/листы, retry, late responses, URL cleanup,
ошибки аудио и отмену загрузки после получения заголовков. Python test_file_preview
проверяет реальные DOCX/XLSX, формулы и запреты доступа до чтения storage.
QA page-canvas содержит только синтетические файлы и подставные Office-ответы:
проверка макета не доказывает фактический запуск серверного парсера.

Для Office необходимы обновления API и web/desktop вместе; миграций нет.
В локальном окружении pytest и types-defusedxml не установлены: Python runtime
тесты и полный mypy пока не подтверждены. Ruff пройден. Упакованный Electron
и настоящий LAN-сайт пока не проверены; сервер не обновлялся.

### Проверка Word PDF — 15 октября 2026

Предыдущий абзац отражает первоначальное внедрение текстового режима. Для новой
конвертации проведены Python-тесты проверки входа/выхода, отказа в доступе до
storage/IPC и ошибок движка, а также frontend-тесты binary/JSON ответов и сохранения
оригинального скачивания. Синтетические настоящие DOCX и DOC дали по две страницы
A4 с рисунком, таблицей и узбекской кириллицей; исходный DOCX не изменился.
В авторизованном тестовом LAN UI оба файла открыты из несохранённого приложения
AI Referent, проверены PDF-страницы и текстовый слой. Письмо не сохранялось/не отправлялось.

Тестовый API до обновления находился на 0095, а исходники уже содержали 0096–0097.
Его штатный startup применил эти существующие миграции поездок: два nullable-поля
и расширение CHECK стадии. Это не новые миграции просмотрщика; перед следующим
обновлением сравнивайте revision БД с head **нового образа/исходников**, а не только
head старого работающего контейнера. Рабочий сервер организации не обновлялся.

PDF API: https://mozilla.github.io/pdf.js/examples/
Версия выбрана совместимой с Node 20 и вне диапазона GHSA-hq66-cqwq-w95j;
после установки `pnpm audit --prod --audit-level high` не нашёл известных уязвимостей.
