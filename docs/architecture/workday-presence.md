# Отметка рабочего дня

Отметка фиксирует действие пользователя в Workspace, а не физическое нахождение в офисе.
Кнопка рядом с профилем явно начинает и завершает рабочую сессию. Повторное нажатие
«Начать» не создаёт вторую открытую сессию. В один день возможны несколько завершённых
сессий, если сотрудник вернулся к работе. История сохраняется, в том числе в субботу
и воскресенье; будущие отчёты смогут выделять такие сессии отдельно.

У каждого сотрудника дневной график по местному времени `Asia/Tashkent`. При отсутствии
индивидуальной записи действует 09:00–18:00. Руководитель может изменить график
непосредственного подчинённого; администратор — другого активного сотрудника. Сервер
проверяет роль, право `team_overview.edit` и подчинённость. Руководителю также нужно
назначенное право просмотра модуля «Обзор команды» — существующая матрица прав не
выдаёт его всем руководителям автоматически. Изменение графика не
переписывает уже начатые сессии: плановое время сохраняется в снимке каждой отметки.

Если открытая сессия осталась незавершённой, после 06:00 следующего календарного дня
API закрывает её расчётным временем окончания по графику (но не раньше фактического
начала). `closed_at` хранит реальное время автоматического закрытия,
`close_source=automatic` отличает его от нажатия сотрудника. Это расчётная граница,
а не подтверждение реально отработанных сверхурочных часов. Операция идемпотентна,
а переход записывается в аудит с `initiator=scheduler`; пользователь в записи —
субъект отметки, а не человек, нажавший кнопку.

Обзор команды показывает число открытых сессий. Согласованные отпуска, больничные,
отгулы и другие отсутствия показываются отдельным статусом; отсутствие отметки
называется «Ещё не отметился», но не «прогул» или «опоздание». Для руководителя доступны
только собственная карточка и непосредственные подчинённые, для администратора — все
активные сотрудники. Графики и состояния читаются из API, не вычисляются в renderer.

Для выпуска требуется миграция `0049_workday_presence`, обновление API и клиента.
Перед применением миграции на сервере нужна обычная проверенная резервная копия БД.
Недельные и месячные отчёты, правила подтверждения рабочего времени, ночные смены и
геолокация в этот пакет не входят.
