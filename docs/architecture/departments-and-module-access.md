# Подразделения и модульные разрешения

**Статус:** реализовано в desktop 0.24.0 / API 0.20.0  
**Миграция:** `0023_department_access`

## Организационная структура

Администратор создаёт подразделения, задаёт уникальный стабильный код и при
необходимости помещает одно подразделение внутрь другого. Сервер проверяет
существование родителя и запрещает циклы. Сотрудник может состоять в одном
подразделении; назначение видно в таблице и карточке сотрудника и записывается в
аудит вместе с изменением роли и должности.

Должность, роль доступа и подразделение остаются разными понятиями. Должность
описывает рабочую функцию, роль задаёт базовый уровень полномочий, а
подразделение группирует сотрудников и уточняет разрешения.

## Вычисление доступа

Для каждого модуля существует пять действий: просмотр, создание, изменение,
согласование и настройка. Эффективное правило вычисляется на сервере в строгом
порядке:

1. базовые права роли;
2. явное правило роли;
3. правила подразделений от корневого к непосредственному;
4. персональное правило сотрудника.

Поздний уровень целиком заменяет предыдущий для выбранного модуля. Удаление
явного правила возвращает наследование. Право «Настройка» включает остальные
действия; создание, изменение или согласование автоматически требуют просмотр.
Суперадминистратор всегда сохраняет полный доступ.

Модульное разрешение не отменяет объектные и доменные проверки. Например,
право согласования само по себе не назначает человека согласующим, а право
изменения задачи не даёт доступ к чужой закрытой задаче. Базовая роль также не
повышается посредством матрицы: административные операции по-прежнему требуют
роль администратора.

## Применение

Проверка выполняется общим серверным слоем до вызова обработчика API. Отдельные
действия процесса — принятие результата задачи, решения по заявкам и поездкам —
дополнительно проверяются по смыслу операции. Поэтому скрытие кнопки в desktop
не является границей безопасности.

Bootstrap возвращает эффективную матрицу текущего пользователя и не включает
данные запрещённых модулей. Desktop скрывает такие пункты навигации и безопасно
показывает первый доступный раздел. Все изменения структуры и явных правил
фиксируются в `audit_events`; правила хранятся в
`core_module_access_rules` с уникальностью уровня, получателя и модуля.

## Интерфейс администратора

В разделе «Сотрудники» доступны два отдельных окна:

- «Подразделения» — создание и редактирование дерева с числом сотрудников;
- «Права модулей» — матрица для роли, подразделения или сотрудника с явным
  обозначением наследуемых и собственных правил.

Таблица сотрудников показывает подразделение, поддерживает поиск и сортировку
по нему. После переназначения состав дерева обновляется без перезагрузки.
