# Курсы валют и погода в верхней панели

Порядок: индикатор соединения/обновлений → USD/UZS → погода Ташкента → уведомления/тема/ассистент → управление рабочим днём → аватарка и имя. Кнопка начала работы и профиль остаются соседями, в том числе отдельной строкой на телефоне. В desktop и браузере используется один компонент; новых разделов навигации нет.

## Источники и смысл данных

- [Официальный JSON ЦБ Узбекистана](https://cbu.uz/ru/arkhiv-kursov-valyut/veb-masteram/): явно запрашивается текущая дата в `Asia/Tashkent`. Валюты USD, EUR, RUB, KZT, CHF, CNY. `Rate` и `Diff` делятся на `Nominal` через Decimal, передаются строками. Отображается дата вступления курса в силу, которая может отличаться от сегодняшней в выходные. Это справочный курс, не банковский курс покупки/продажи. Пересчёт — локальное вычисление, не платёж.
- [Open-Meteo Forecast](https://open-meteo.com/en/docs): модельные текущие значения, температура в °C, ветер в м/с; время передаётся Unix timestamp и выводится по Ташкенту. Город Ташкент и 12 областных центров; Ташкентская область — Нурафшан. Это оценка для точки, не среднее по области.
- [Open-Meteo Air Quality / CAMS Global](https://open-meteo.com/en/docs/air-quality-api): US AQI, PM2.5, PM10, озон и диоксид азота. Концентрации в мкг/м³; модель, не показания локального датчика. В панели есть атрибуция Open-Meteo/CAMS/CC BY 4.0.
- Владелец подтвердил некоммерческое внутреннее использование без рекламы, продажи или платных подписок. Оно соответствует [условиям бесплатного Open-Meteo](https://open-meteo.com/en/terms). При коммерциализации необходимо пересмотреть лицензию и перейти на подходящий тариф, а не продолжать использовать бесплатный endpoint.

## Сервер и устойчивость

Два read-only endpoint под существующей авторизацией: `GET /api/v1/context/exchange-rates`, `GET /api/v1/context/weather`. Новых таблиц, миграций, прав администратора, геолокации пользователя и секретных ключей нет. Провайдерам отправляются только фиксированные публичные координаты; токен сессии и данные сотрудников не передаются.

Каждый процесс API использует независимые single-flight кэши: валюты 15 минут, погода 10 минут, воздух 30 минут. Изменение ташкентской даты обновляет ключ курса и дневного прогноза. После ошибки повтор не чаще раза в минуту. Последние данные разрешены не дольше 3 дней / 2 часов / 6 часов соответственно и явно помечаются устаревшими. Без пригодного кэша показывается отсутствие данных. Отказ воздуха не блокирует погоду. Кэш не является новым offline-режимом приложения.

Внешние запросы ограничены таймаутом и размером ответа 1 МБ; нет произвольных URL, пересылки авторизации и переходов по redirect. Проверяются дата, единицы измерения, порядок/число точек и диапазоны. В логах только имя провайдера и класс ошибки, не содержимое ответа.

Renderer отменяет запросы старой сессии, приостанавливает опрос скрытой вкладки и не допускает перекрывающихся запросов. «Обновить» повторяет чтение через общий серверный кэш и не создаёт запрос к провайдеру от каждого сотрудника.

## Интерфейс и проверка

Используются Fluent Popover, семантические цвета и существующие `DialogResizeMotion` / `useContextMotion`: плавное изменение панели без масштабирования текста. У вкладок клавиатурный фокус, Escape возвращает фокус инициатору; при возврате из области восстанавливается выбранная строка. На сенсорном экране основные цели не меньше 48px; длинный список и детали прокручиваются внутри ограниченной панели. Учитываются reduced-motion и forced-colors.

Синтетическая QA-страница `apps/desktop/qa/topbar-context.html` использует настоящие компоненты, не создаёт сотрудников и не изменяет рабочие записи. Сценарий `scripts/topbar-context-smoke.cjs` проверяет обе темы в Edge и WebKit, открытие валют/пересчёт, 12 областей, детали, размеры, доступность и возврат фокуса. Скриншоты сохраняются в игнорируемый `tmp/topbar-context`. QA-данные не импортируются production-компонентом. WebKit — движок для предварительной проверки Safari, не свидетельство тестирования настоящего iPhone/iPad; физические устройства отдельно не проверены.

## Доставка

Для функции необходимо совместное обновление API и web; старый API покажет честную ошибку в панели, остальные разделы продолжают работать. Миграция базы не нужна. Собирается проверенный `main`, затем применяется штатный `scripts/lan/deploy-web.ps1` только к тестовой конфигурации. Нельзя объявлять LAN-сайт обновлённым до проверки `version.json`, API ready и самого адреса. Рабочий офисный сервер автоматически не обновляется. Изменение renderer не доказывает установку нового EXE.
