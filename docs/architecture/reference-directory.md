# Справочник организации

Первый этап хранит одну карточку «Юксалиш» без заранее внесённых юридических
реквизитов. Название, ИНН, адреса, контакты и банковские поля заполняет
уполномоченный сотрудник; данные не извлекаются из существующих документов и
не угадываются. Возможность нескольких собственных юрлиц остаётся отдельным
будущим изменением схемы и интерфейса.

Другие организации разделены по типам (партнёр, донор, госорган, подрядчик,
прочее). Действующие записи проверяются на повтор названия и ИНН. Эксперт может
быть связан с одной действующей организацией, но может существовать без неё.
Архив скрывается обычным фильтром и не удаляет запись или аудит.

Шаблон описывается назначением, языком и краткими правилами применения.
Файл PDF, DOCX или XLSX загружается отдельной версией в приватное хранилище;
прежние версии сохраняются для просмотра и скачивания. Незавершённая карточка
без файла видна редакторам, но не показывается обычным читателям. Загрузка
проверяет размер, расширение и сигнатуру документа. Генерация документов с
автоматической подстановкой реквизитов в первый этап не входит.

## Доступ и аудит

Новый модуль `reference` включён в каталог и личный порядок навигации без
сброса уже сохранённого порядка. Все сотрудники по умолчанию могут читать;
создание и изменение по умолчанию доступны только администраторам. Матрица
разрешений может отдельно выдать права `create` и `edit` другим сотрудникам.
Сервер проверяет доступ на каждом маршруте. Изменения карточек и загрузки
версий фиксируются в общем аудите; последние события видны в раскрывающейся
истории на вкладке собственной организации. Конфликт ревизии возвращает 409 и
не затирает чужую правку.

## Поставка

Миграция `0108_reference_directory` создаёт профиль и таблицы организаций,
экспертов, шаблонов и версий файлов. Сначала обновить API и применить миграцию,
затем web/desktop. Рабочая БД не заполняется фиктивными реквизитами. Старые
клиенты игнорируют новый пункт, новые клиенты на старом API не получают его из
каталога доступа. Интеграционный тест требует отдельной PostgreSQL-базы через
`YUKSALISH_TEST_DATABASE_URL`; производственную БД для проверки не использовать.
