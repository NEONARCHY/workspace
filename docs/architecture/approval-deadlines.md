# Напоминания и эскалации по срокам заявок

**Статус:** реализовано в desktop 0.23.0 / API 0.19.0  
**Миграция:** `0022_approval_deadlines`

## Правила

Источник времени — поле «Срок оплаты» самой заявки. Для каждого активного блока
согласования сервер использует его собственную конфигурацию:

- `reminderHoursBefore` — моменты напоминаний до срока, по умолчанию 24 и 2 часа;
- `escalationAfterHours` — задержка эскалации после просрочки, по умолчанию 4 часа;
- `escalationUserId` — явный получатель; без него используется создатель опубликованного маршрута.

Напоминания получает фактический согласующий активного этапа: делегирование,
конкретный сотрудник, должность и роль учитываются теми же правилами доступа, что
и само решение. На доработке получателем становится инициатор. При наступлении
просрочки инициатор уведомляется даже тогда, когда он не согласующий.

## Доставка без дублей

Планировщик API проверяет сроки раз в минуту. Событие однозначно определяется
заявкой, сроком, этапом, получателем, типом и порогом. Уникальное ограничение
`uq_approval_deadline_delivery` делает повторный запуск безопасным: рестарт,
несколько вызовов планировщика или повторная загрузка интерфейса не создают
одинаковых уведомлений.

Если сервер впервые увидел заявку уже рядом со сроком, он отправляет только
наиболее актуальное из достигнутых напоминаний, а не несколько устаревших сразу.
Изменение срока образует новый цикл контроля; старый аудит сохраняется.
Завершённые, отклонённые и отменённые заявки больше не обрабатываются.

Все отображаемые даты приводятся к часовому поясу Ташкента. Уведомления попадают
в постоянный центр приложения и используют существующую управляемую Windows-
доставку. Пользовательские настройки всплывающих уведомлений не удаляют события
из внутренней очереди.

## Интерфейс и аудит

На карточке доски показывается контекстная плашка «Осталось» или «Просрочено».
В подробной карточке доступны срок, следующее событие, плановая эскалация,
действующее правило и последние доставки с именами получателей. В конструкторе
маршрута администратор задаёт оба интервала напоминаний, задержку эскалации и её
получателя отдельно для каждого блока согласования.

Таблица `approval_deadline_events` является аудитом фактических доставок и не
используется для автоматических штрафов или оценки эффективности сотрудников.

## Проверки

- PostgreSQL-интеграция проходит стадии 24 часа → 2 часа → просрочка → эскалация,
  проверяет получателей, аудит и идемпотентность.
- UI-тесты проверяют все состояния остатка времени и отображение блока контроля.
- Общий quality gate включает миграцию чистой базы, Ruff, mypy, pytest, ESLint,
  TypeScript, security-сканирование и production build.
