# HR: локальное заполнение по ID-карте

В «Приёме на работу» кадровик может выбрать одно или два фото JPEG/PNG (лицевая и
обратная стороны), отдельно запустить распознавание и проверить предлагаемые ФИО,
JSHSHIR и серию/номер документа. Пока кадровик не выбрал поля и не подтвердил сверку
по оригиналу, форма не меняется. Заполненные поля не выбраны по умолчанию; каждую
замену человек подтверждает явно. Ручной ввод, сохранение черновика и прежний маршрут
подписания остаются доступными при отсутствии/сбое OCR.

## Приватность и точность

- Только локальный Tesseract. Gemini и другие внешние сервисы не вызываются.
- Фото не записывается в MinIO, кадровый пакет или временный файл приложения. CLI
  получает нормализованный PNG через stdin, вывод TSV — через stdout; EXIF удаляется.
- Ответ и ошибки no-store/nosniff. Имена файлов, изображения и OCR-текст не входят
  в URL/аудит. Система не сохраняет «сырой OCR-текст» рядом с карточкой.
- POST `/api/v1/hr/hiring/identity-card/recognize` проверяет право редактирования HR
  и кадровое полномочие до чтения тела/запуска движка. Председатель или обычный
  сотрудник с просмотром HR не получает распознавание только из-за видимости раздела.
- До 5 МиБ на фото, 200 пикселей по меньшей стороне, до 12 мегапикселей; после
  проверки сторона уменьшается максимум до 2200 пикселей. Только одиночный JPEG/PNG.
- Два параллельных процесса на API-процесс, один OCR-поток, тайм-аут 25 секунд,
  вывод ограничен 128 КиБ. Сбой/отмена завершает дочерний процесс; stderr не логируется.
- Извлечение консервативное: нужны подписи полей на узбекском/русском/английском;
  неуверенная строка исключается целиком. Несколько разных значений оставляют поле
  пустым. Буквы O/I не превращаются автоматически в цифры. Между сторонами карты
  конфликтующие значения также не выбираются автоматически.
- 14 цифр — проверка формата, не подтверждение личности или подлинности документа.
  Отчество/непрочитанное поле человек дополняет вручную. Точность на всех реальных
  макетах и условиях съёмки не гарантируется: перед выпуском нужна проверка
  согласованных образцов на тестовом сервере, без включения личных файлов в Git.

Многоязычный TSV и параметры CLI соответствуют
[официальной документации Tesseract](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html).

## Обновление сервера

Миграция не требуется. Runtime и dev Dockerfile устанавливают Tesseract и языки
eng/rus/uzb/uzb_cyrl из системного менеджера пакетов. Требуется пересборка API-образа,
затем обновление web/desktop; один frontend не устанавливает OCR на старом сервере.
Настройка `YUKSALISH_HR_IDENTITY_OCR_EXECUTABLE` — абсолютный путь к доверенному
исполняемому файлу, по умолчанию `/usr/bin/tesseract`. Путь не принимается от клиента.
Для запуска API вне Docker нужны соответствующие Tesseract и языковые модели;
Windows-комбинация требует отдельной проверки. Если движок отсутствует — 503 с
понятной подсказкой, без скрытого переключения на облако. Приём на работу продолжает
работать вручную. Не отключать TLS/права для проверки распознавания.

## Дизайн и приёмка

HR сохраняет общий сине-бирюзовый заголовок Workspace, Inter, семантические токены
светлой/тёмной темы. Рабочие действия отделены от шапки, вкладки собраны в локальную
навигацию, карточки/реестры — в спокойные поверхности. В приёме список оформлений
остаётся рядом с контекстом; этапы не обходят защищённые серверные переходы.
Формы адаптируются до одной колонки, editor имеет отдельную верхнюю строку и
внутреннюю прокрутку. Блок ID-карты использует те же поля и явную проверку.

Локальная сборка API и синтетический smoke реального OCR в контейнере без сети
проверены. Итоговый прогон на новой изолированной PostgreSQL-базе: 950 passed,
2 skipped, покрытие 84,03%; desktop — 145 файлов, 1038 passed, 1 skipped.
TypeScript, ESLint изменённых файлов, Ruff, строгий mypy, полный Bandit, сборка
renderer/main/preload и проверка заметок/workflow прошли. Unit/UI и транзакционные
тесты используют только синтетические данные.
Браузерная проверка локального stand заблокирована ERR_BLOCKED_BY_CLIENT;
блокировка не обходилась. Живая приёмка светлой/тёмной темы, 1024×768, компактного
окна, 200%, клавиатуры и упакованного Electron остаётся отдельным выпускным условием.
Рабочие серверы/данные не обновляются этой задачей автоматически.
