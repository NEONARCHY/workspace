# Корпоративный ассистент: источники и границы доступа

Ассистент может помочь с тремя видами вопросов: сведения о движении «Юксалиш»,
личный рабочий контекст сотрудника и редактура текстов. Примеры запросов: «Какие
акции проводили в 2023–2026 годах?», «Что нового у меня?», «Какие мои задачи требуют
внимания?», «На какой стадии моя заявка?», «Сделай короткий текст для коллег».

## Публичные сведения

`scripts/build-organization-knowledge.py` собирает общедоступные HTML-страницы
официального `yumh.uz`: переданные владельцем разделы, каталог проектов, архив
новостей и текст PDF, размещённых в разделе книг на том же домене. Проверенный снимок
хранится в `organization_knowledge.json` и входит в
сборку API. Ответ получает ограниченные по объёму фрагменты с датой и URL источника;
модель обязана отмечать нехватку источников и не выдавать предположения за факты.

Чтобы добавить новые публикации, разработчик повторно запускает скрипт перед
выпуском, проверяет число собранных страниц и изменения файла, затем публикует
API. Обычный `git pull` без пересборки контейнера не обновляет уже запущенный API.
Снимок не включает сканированные PDF без текстового слоя, внешние сайты и публикации, появившиеся после
указанной в JSON даты. Поэтому нельзя обещать буквальное знание «всего» или
актуальность без обновления индекса.

## Рабочий контекст

Только сервер выбирает записи для передачи модели. Задачи ограничены автором,
исполнителем и участником при наличии права на модуль; проекты — правом на модуль.
В личном контексте заявок и поездок используются только собственные/закреплённые
объекты; названия активных этапов заявок берутся из доступного маршрута.
Последние публикации корпоративной ленты передаются модели только при действующем
праве просмотра ленты. Уведомления повторно проверяют текущую видимость связанной задачи,
заявки, поездки или чата; старое уведомление не восстанавливает отозванный доступ.
Названия и тексты источников считаются данными, а не инструкциями модели.

По вопросам о конкретном сотруднике ассистент использует активный справочник только
при праве просмотра сотрудников. Должность, подразделение, подтверждённый стаж,
награды и открытые достижения берутся из уже доступного профиля признания. Число
активных задач подчиняется настройке видимости профиля. Показатель выполнения задач
в срок берётся только из последнего дневного агрегата и только при праве просмотра
общей эффективности; период и дата снимка указываются явно. Содержимое чужих задач,
финансовые поля и достижения, связанные с оплатами, в контекст не передаются.
В старом реестре при праве просмотра проектов показываются только текущие проекты,
где сотрудник назначен руководителем. В проектном пространстве дополнительно
показываются его роли участника, согласующего, ответственного или исполнителя задач
лишь по объектам, которые открыты спрашивающему сотруднику. Названия проектов
ограничены по объёму; бюджеты и содержимое задач не передаются модели.
Поиск имени сопоставляет кириллицу и латиницу, а также распространённые падежные
окончания. Если запрос «кто такой Бобур» или «кто такой Темур ака» подходит
нескольким сотрудникам, сервер сразу возвращает найденные полные имена и должности
из доступного справочника и просит уточнить человека, не поручая выбор модели.

Это не универсальный поиск по каждому модулю Workspace: например, документы и
вложения не индексируются, а стадии согласования, где сотрудник только временный
согласующий, пока могут быть представлены его уведомлением, но не полной карточкой.
При отсутствии контекста ассистент должен честно сообщить об этом.

## Сообщения и голос

Кнопка в композиторе мессенджера предлагает пять стилей. Перегенерация не меняет
черновик; замена происходит только после явного нажатия и недоступна, если исходный
текст изменился. Сервер не читает чужой чат для переписывания: отправляется только
текст, который пользователь сам ввёл. Голосовой ввод по явному разрешению
микрофона записывает не более минуты WebM/Opus, отправляет запись через
авторизованный API на распознавание и вставляет полученный текст в черновик без
автоматической отправки. Аудио и рабочие фрагменты уходят внешнему провайдеру ИИ;
ключ находится только на сервере.
В чате можно прикрепить один DOCX, PDF, PNG, JPEG, WebP или UTF-8 TXT до 5 МБ. Сервер
проверяет формат и размер, передаёт содержимое модели только с текущим запросом,
но не сохраняет файл в истории: в ней остаётся лишь его название. Для следующего
вопроса о том же файле его нужно приложить повторно. Из DOCX извлекается только
читаемый текст; картинки внутри него не передаются модели.

## Режимы и диалог

Иконка использует адаптированный шейдер React Bits Orb из кода владельца:
кольцо в фирменных бирюзовом #0091A8 и тёмно-синем #293A55 с сине-фиолетовыми
переливами, без зелёного, с прозрачным центром и без чёрной подложки. При наведении
или фокусе плавно меняются яркость и движение света, без увеличения, подъёма
или деформации от hover. CSS-вариант встроен в существующий React Three
Fiber, без новой зависимости OGL или Tailwind. Анимация приостанавливается
в скрытой вкладке и вне экрана; уменьшенная анимация, высокая контрастность
и ошибка графического контекста переключают орбу на статичное кольцо.
Кнопка занимает отдельное место в верхней панели рядом с профилем, а не поверх
нижних действий страниц. Она остаётся на месте при открытии диалога;
закрытие возвращает на неё фокус. Сам диалог закреплён относительно окна,
его адаптивные размеры и раскрытие сохранены. При запрете ассистента место
под кнопку не резервируется.

В интерфейсе доступны «Лёгкий» (по умолчанию), «Рабочий» и «Фокус».
Их серверные модели соответственно: `gemini-3.5-flash-lite`, `gemini-3.5-flash`
и `gemini-3.8-flash`. Дорогая Pro-модель больше не предлагается. Выбор модели
не меняет доступ к корпоративным данным: контекст по-прежнему отбирает сервер.
Если сотрудник выбирает «Ответить» по правой кнопке мыши на прежнем ответе,
короткая цитата включается в новое сообщение и остаётся в истории. Это цитирование
текста, а не отдельная серверная ветка диалога. Окно ассистента сразу занимает
конечное место; анимация меняет только прозрачность и смещение. Во время записи
статус «Слушаю» показывается в переписке.
Шаблоны запросов доступны и после начала переписки; они лишь заполняют поле ввода
и не отправляют сообщение автоматически. Скрытые внутренние рассуждения модели не
показываются пользователю. Под ответом раскрывается перечень проверенных рабочих
источников и приложенного к текущему запросу файла. Это прозрачность источников,
а не скрытые рассуждения и не гарантия, что модель использовала каждый из них.
Перечень сохраняется вместе с новым ответом; для старых ответов его нет. Для
развёртывания этой версии API сначала применяется миграция
`0065_assistant_source_labels`, затем `0066_assistant_references`; в общей ветке
они завершаются миграцией `0067_merge_workspace_features` (`alembic upgrade head`).
После этого обновляются сервер и desktop-клиент.

## Подготовка действий и выключение ассистента

Явная просьба создать задачу, проект, поездку, отсутствие/отгул, публикацию в
ленте или сообщение превращается в черновик. Сервер извлекает только указанные
поля и проверяет право создания или изменения в целевом разделе. При нехватке
обязательных сведений ассистент задаёт уточняющий вопрос. После нажатия «Открыть
заполненную форму» пользователь проверяет и меняет поля в существующей форме
Workspace и отдельно подтверждает сохранение. Голосовой ввод сперва вставляет
распознанный текст в композитор; он не создаёт запись сам. Для нового личного
сообщения сначала показываются получатель и текст; создание диалога требует
отдельного нажатия, а отправка сообщения — следующего явного действия.

Администратор может запретить ассистент отдельному сотруднику в правах доступа
или отключить его всем проверенным региональным подразделениям. Запрет уровня
подразделения нельзя обойти персональным разрешением. Для администратора
допускается персональное отключение только ассистента; остальные его модульные
права сохраняются. Суперадминистратор остаётся исключением для восстановления
доступа. При запрете кнопка ассистента не монтируется, поле страницы занимает
освободившееся место, а сервер отклоняет запросы к истории, ответам, голосу и
переписыванию текста. Ранее сохранённые ответы не удаляются, но не читаются до
возврата права.
