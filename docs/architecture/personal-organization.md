# Личная организация — desktop/API 0.14.0

## Чаты

Меню `…` справа у чата появляется при наведении/фокусе (на сенсорном экране доступно постоянно). Оно предлагает закрепление, открепление, архивирование и возврат из архива.

- Закреплённые чаты находятся выше остальных; новый закреплённый чат добавляется первым. Разрешено до 100 закреплений.
- Их порядок меняется перетаскиванием на другую закреплённую строку либо действиями «Переместить выше/ниже». Обычные строки и внешние данные перетаскиванием не закрепляются.
- Во время поиска перестановка отключена: невидимые результаты не должны неожиданно менять порядок. Поиск продолжает находить названия и неудалённые сообщения внутри выбранной папки.
- Архив доступен рядом с вкладкой «Чаты» и показывает число чатов и индикатор непрочитанных. Это личная папка, а не удаление, выход из группы или отключение уведомлений.
- Архивирование снимает закрепление. Возврат не закрепляет чат повторно. Новое сообщение само по себе не возвращает чат в основной список; прежние уведомления продолжают работать.
- Открытая переписка при архивировании остаётся смонтированной: черновик, ответ и файлы не сбрасываются. Над ней появляется пометка архива с кнопкой возврата. Переход из уведомления может открыть архивный чат сразу.
- Действия недоступны, пока сохраняется текущая операция. При отказе сервера строки остаются на прежних местах, ошибка показывается явно, а данные перечитываются.

## Главное меню

Маленький карандаш под логотипом открывает встроенный редактор бокового меню. Он работает и из свёрнутой панели, раскрывая её на время редактирования. Сворачивание в этот момент отключено, чтобы не обрезать редактор.

Переставлять можно все 11 кнопок, включая уведомления и настройки. Есть перетаскивание, стрелки выше/ниже, «Сохранить», «Отмена» и «По умолчанию». Только сохранение отправляет новый порядок на сервер. Профиль сотрудника остаётся внизу; две последние кнопки меню визуально отделены нижней зоной, как в исходной раскладке.

Изменяется только очередность: разделы не скрываются, их доступность и права не меняются. Новые известные разделы добавляются к сохранённому порядку автоматически. Стандартный порядок сохраняет последовательность девяти Bitrix-разделов, затем уведомления и настройки.

## Хранение, изоляция и синхронизация

Аддитивная миграция `0017_personal_organization` создаёт `workspace_personal_preferences` с PK/FK `user_id`, JSONB-массивами `pinned_chat_ids`, `archived_chat_ids`, `navigation_order` и целой `revision`. Таблицы сообщений, участников, задач и согласований не меняются. Пока настройки не редактировались, чтение возвращает стандартные значения без создания строки.

- Пользователь определяется только авторизованной сессией, а не параметром запроса. Даже администратор Workspace не может закрепить или архивировать чужой приватный чат, в котором не состоит.
- Чтение фильтрует устаревшие ID по актуальному участию в чатах. Исключённый участник не получает идентификаторы недоступной группы через настройки.
- Изменения одной строки сериализуются блокировкой `FOR UPDATE`: параллельные закрепления не теряют друг друга. Операции закрепления/архивирования повторяемы, без дублей.
- Перестановка требует текущей ревизии и полного списка уникальных ID. Навигация должна содержать все 11 известных разделов. Подмена пользователя, дубликаты, неизвестные разделы и неполные порядки отклоняются.
- Открытый редактор хранит начальную ревизию; чужое изменение в другом окне приводит к явному конфликту, а не перезаписи нового порядка. Старый bootstrap не затирает уже полученный более новый ответ.
- После коммита событие `personal.preferences` отправляется только соединениям того же пользователя. Настройки включены в bootstrap и доступны на других устройствах; localStorage для них не используется.

API:

- `GET /api/v1/personal-preferences` — личные настройки.
- `PATCH /api/v1/personal-preferences/chats/{chat_id}` — `action: pin | unpin | archive | unarchive`.
- `PUT /api/v1/personal-preferences/pinned-chats` — `chatIds`, `revision`.
- `PUT /api/v1/personal-preferences/navigation` — `order`, `revision`.

## Проверка и доставка

Проверки PostgreSQL/HTTP выполняются только в `yuksalish_test`: повторный вход, изоляция двух пользователей, отсутствие доступа у стороннего администратора, архив/возврат с сохранением сообщений, новый контент в архиве, параллельные закрепления, конфликт ревизии, защита полного порядка и фильтрация после исключения участника. Отдельно проверена адресная доставка событий.

Frontend unit-тесты проверяют порядок, дефолты, ревизии, отмену, ошибки и папки чатов. `scripts/personal-organization-smoke.cjs` проверяет реальные Fluent-меню и drag&drop в Edge и, через `ORGANIZATION_ELECTRON_EXE`, в упакованном Electron. Мутации этого UI-сценария остаются в памяти тестового клиента. Серверное хранение проверяется отдельным HTTP-тестом, а не подменяется UI-моком.

Дополнительные регрессии: адаптивные раскладки, сообщения, конструктор согласования и защита от полноэкранных порталов Fluent. Локальный API обновлён до 0.14.0, миграция применяется автоматически при его запуске; для этой desktop-функциональности требуется обновлённый API.

Результаты: 84 frontend-теста, 52 Python-теста (общее покрытие 81.47%), lint/typecheck, mypy, bandit, 83 проверки раскладки, 11 проверок конструктора/порталов и сценарий сообщений. Полный сценарий личной организации пройден в Edge и готовом Electron. Первый нативный прогон был прерван закрытием тестового окна; повторный прогон после завершения упаковки прошёл полностью.
