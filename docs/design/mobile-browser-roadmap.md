# Адаптация браузера для телефонов и планшетов

Начало: 13 октября 2026. База: `origin/main` f302ccc после pull.
Цель: iPhone/iPad Safari и Android Chrome, обе ориентации. По выбору владельца
навигация открывается кнопкой ☰, все доступные разделы и их порядок сохраняются.
Это адаптация React/Fluent web, не новое приложение или замена Inter/палитры.
Офлайн-редактирование, новые API и миграции не входят в эту работу.

### Итерация 2: мессенджер, рабочие таблицы, большие формы

EmployeeRecords и общий record composer. На телефоне таблицы становятся

ясность 5 + accessibility 4 − complexity 2 − performance 2 − network 1 = MFRI 4;

по последнему указанию владельца. Фактический CI/merge проверяется в GitHub,
а не выводится из локальных проверок. Выкладка серверов не выполняется.

Стенд `mobile-workflows-smoke.cjs` проверяет реальные пять модулей, бюджет/импорт,
24 проектные заявки, 12 оплат/поездок и 5 событий одного дня. На 320×700,
390×844, 768×1024, 1024×768, 1180×820 (touch) и 1440×900 проверены локальная
прокрутка, списки, Escape, сохранение значения/фокуса при повороте, 16px ввод,
footer в сокращённом VisualViewport и ошибка бюджетной статьи без потери ввода.
Компактные шапки и рабочие панели сравниваются по обеим границам с допуском 1px,
включая смену раздела и режим списка; крупные intentional колонки не приравниваются
к ширине страницы. Результаты и PNG — `tmp/mobile-workflows/`, не коммитятся.
Все данные синтетические; серверные запросы перехвачены, реальных операций нет.

Исправлена потеря modal focus при замене кнопки «Добавить статью» формой и после
ошибки сохранения: фокус переводится в действительное поле, затем возвращается
к кнопке при закрытии формы. Проверка согласия, права, точные суммы и ключи повтора
не ослаблялись. WebKit/Safari/настоящие OS keyboards, VoiceOver/TalkBack и FPS
по-прежнему не подтверждены этой Chromium-проверкой.

Платформы: web Safari iOS/iPadOS и Chrome Android. Стек: существующий React,
Fluent UI и CSS. Прочитаны mobile-design-thinking, touch-psychology,
mobile-performance, mobile-backend, mobile-testing, mobile-debugging,
platform-ios, platform-android; native-only примеры не переносим в браузер.

Компоненты первой итерации: меню → выбор раздела; шапка → поиск/статус/профиль;
canvas → рабочий контент. Многим разделам не подходит нижний ряд из 4–5 вкладок:
сохраняем согласованный drawer, а не отбрасываем пункты. Узкая постоянная
полоса тоже отклонена: на 360 px она расходует существенную часть экрана.
Состояние открытия локальное; состояние страницы не переходит в новый store.

Принципы: сенсорные цели 48 CSS px; видимое закрытие и неизменные серверные
подтверждения; transform/opacity только для коротких переходов, без новых loops.
Избегаем уменьшенной копии desktop и действий, доступных исключительно жестом.
Safari: safe-area, динамическая область просмотра, отсутствие запрета pinch zoom.
Chrome: та же компоновка и клавиатурное уменьшение viewport. Не перехватываем
системные edge-жесты, не рисуем вымышленные статусные панели/рамку телефона.

MFRI для всей системы отрицательный из-за таблиц, форм и тяжёлых окон: поэтому
адаптация разбита на этапы. Для ограниченного MOB-1/2: ясность платформы 5,
готовность доступности 4, сложность 1, performance risk 1, network dependence 1:
индекс 6. Фактический FPS и пригодность всех экранов не следуют из этой оценки.
В этой итерации не добавляем native pinning, push, offline queues или зависимости.
