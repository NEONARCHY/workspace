База: `e30f775e4230804b26a60fd546dc9218f2288858`, ветка `feature/ui-consistency-iteration-12`.
Рабочая ветка: `feature/ui-consistency-iteration-14`. Интеграция только через PR в родительскую ветку, без самостоятельного merge.
Перед отправкой ветка перенесена на обновлённую родительскую базу `529f8f5729a562f2dffc48527cdea6fd1986bf5c`; собственный diff остался в пределах этих трёх экранов и новых вспомогательных файлов. Профильные тесты, TypeScript, сборка и браузерные проверки повторены после синхронизации.

## Визуальное направление

Спокойное рабочее пространство для настройки прав, структуры и меню. Сохранены Inter, Fluent UI, существующие тематические переменные и смысловые цвета. Главные ориентиры — выбранный субъект и доступные действия; поверхности отличаются близкими оттенками и расстоянием. Декоративные рамки, inset-тени и кромки не добавляются. Подход: [unslop](https://github.com/heydamir/unslop), Damir Sokolovsky, CC BY 4.0.

## Подтверждённые оптимизации

- Матрица больше не строит карту подразделений для каждого разрешения и не ищет правило линейно при каждом обращении: отдельные индексы правил и иерархии переиспользуются до изменения соответствующего массива. Семантика первого совпадения сохранена.
- При построении дерева убрано копирование всего массива соседей на каждом добавлении. Данные сортируются и обходятся как прежде, с защитой от циклов.
- Поисковая строка и принадлежность сотрудников к ЦА/регионам индексируются при изменении справочника. Выбор checkbox не повторяет подготовку всего списка.
- На синтетических данных начальное число `.department-member-row` снижено со 120 до 25. Поиск работает по всем 120, выбранные ID хранятся независимо от видимой порции. Это сокращение DOM; ускорение в миллисекундах и уменьшение сетевой загрузки не заявляются — справочник уже приходит целиком.
- Список людей для выбора меню мемоизирован и не создаётся заново при каждом переключении раздела. Новых сетевых запросов при поиске и фильтрации нет.
- В административных формах поиск не использует анимацию расширения: не создаются её наблюдатели размеров и таймеры морфинга для этих полей.
- Переиспользован существующий прогрессивный список с отключением IntersectionObserver; новый обработчик фокуса удаляет подписки после последнего потребителя.

## Фокус только после Tab

Три экрана используют `useTabFocusMode`: Tab и Shift+Tab включают видимый индикатор; pointerdown, потеря фокуса окна и Win/Meta его выключают. Shift сам по себе, ввод текста, программный focus и системные сочетания его не включают. DOM-фокус, работа клавиш, ввод текста и функциональное выделение сохраняются.

Общие файлы не изменены. Для всего приложения подготовлен отдельный патч `docs/design/patches/iteration-14-tab-focus.patch`. Он подключает хук в App и добавляет финальное правило видимости фокуса. После интеграции этой ветки основной чат должен выполнить:

```powershell
git apply --check docs/design/patches/iteration-14-tab-focus.patch
git apply docs/design/patches/iteration-14-tab-focus.patch
```

Патч требует отдельной проверки общих экранов в основной ветке. До применения глобальное поведение остальных разделов не считается изменённым.

## Полный ручной CI

Автоматический workflow настроен только на PR в main, поэтому для stacked PR запущен [ручной CI](https://github.com/NEONARCHY/workspace/actions/runs/46002481760) на коммите `b0e1419860b5175582a7d646fe0d21001dfe243c`. Четыре UI-шарда, desktop-checks, web-image-checks и release-notes прошли; secrets в ручном запуске пропущен настройкой workflow.

Python выявил унаследованную ошибку подготовки данных: `test_messenger_http_contract`, строка 981, ожидает 403, получает 404. Сценарий запрета pin/unpin удаляет `third_id` из группы на строках 945–949. Следующая прежняя проверка передачи владельца и самостоятельного выхода предполагает, что участник всё ещё существует. Сервис закономерно возвращает «Участник не найден».

Подготовлен отдельный патч `docs/design/patches/iteration-14-parent-test-prerequisite.patch`: он восстанавливает участника перед проверкой передачи владельца и сохраняет прежние строгие ожидания 403 и 204. Серверная авторизация и общий тестовый файл напрямую не изменены. `git apply --check` прошёл; основной чат должен применить патч в своей области и повторить PostgreSQL-сценарий. До этого полный CI не считается зелёным. Последующее дополнение отчёта и патча не меняет проверенный UI-код.

## Ограничения

- UI не подменяет серверные проверки авторизации. API, contracts, БД и миграции не менялись.
- Синтетический браузерный стенд не доказывает работу установленного Electron и авторизованной рабочей среды.
- Общая дорожная карта, App, main, глобальные стили, CI и компоненты итерации 13 не редактировались.
- Сборка сохраняет прежние предупреждения о крупных чанках и смешанном статическом/динамическом импорте; они не устранялись в этой области.
- Один параллельный прогон Vitest завершился ENOSPC. После освобождения места профильный прогон выполнен последовательно; правила проверок не ослаблялись.
