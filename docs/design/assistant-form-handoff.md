# Ассистент: обсуждение → заполненная форма

## Поведение

Четыре кнопки подготовки передают выбранный тип действия отдельно от текста.
Они заполняют редактор; пользователь отправляет запрос самостоятельно. Сервер
проверяет действующее право создания соответствующего объекта до обращения к модели.
Явная просьба о другом действии заменяет выбранный сценарий, а уточнение продолжает
последний черновик только в том же личном чате.

Ассистент извлекает явно сообщённые поля, задаёт вопросы о недостающих обязательных
данных и хранит только черновик в истории ассистента. У задачи уточняется исполнитель,
у проекта — руководитель, у поездки — участники. Для частичного отсутствия требуется
точное время; бюджет без валюты и обратный интервал не считаются готовыми.

Команда **«Открывай форму»** (или кнопка «Открыть заполненную форму») открывает
настоящую форму Workspace с согласованными данными и закрывает окно ассистента.
Команда не означает сохранение: пользователь проверяет и изменяет форму, затем
нажимает её обычную кнопку создания/сохранения. Простое «да», вопрос, отрицание
и команды с дополнительными изменениями не открывают форму автоматически.
«Да, всё верно» продолжает согласование, сохраняя готовый черновик для явного сигнала.
«Измени срок…», «Бюджет: …» и кнопка уточнения продолжают подготовку готового черновика.
При неудаче открытия согласованные данные и текст сигнала сохраняются для исправления.

## Поля

- Задача: название, описание, ответственный, срок, приоритет, метка проекта,
  соисполнители, наблюдатели и чек-лист. Метка проекта остаётся прежним текстовым
  полем задачи и не создаёт связь с новым проектным пространством.
- Проект: название, код, описание, руководитель, даты, целочисленный бюджет,
  валюта, открытый/закрытый доступ, ответственные и упорядоченный маршрут согласующих.
- Поездка: цель, направление, даты и участники. Стоимость не добавляется:
  у существующей формы поездки такого поля нет.
- Отсутствие: тип, причина и интервал. Отпуск/больничный могут использовать даты
  с обычными значениями времени формы; отгул/опоздание/мероприятие требуют времени.

Неуказанные необязательные настройки остаются обычными начальными значениями формы
(например, стандартный приоритет или открытый доступ), а не утверждаются как выбор
пользователя. В модели списки имён и чек-лист передаются строками с переводами строк;
идентификаторы из ответа модели не принимаются. Клиент разрешает имена по актуальному
активному справочнику, поддерживает явное «я», сохраняет порядок и убирает дубли.
Неизвестное или неоднозначное имя останавливает открытие вместо подмены человеком.

## Границы и выпуск

Подготовка не создаёт задач/проектов/заявок/чатов; окончательный запрос выполняют
существующие обработчики форм. Сервер повторно проверяет их права, обязательные поля,
конфликты и маршруты согласования. Состояния завершения и утверждения не задаются ИИ.
Новые таблицы и миграция не требуются. Для полноценного режима обновляются API
и web/desktop; старый API не извлекает расширенные поля.

`qa/assistant-actions.html` — явно помеченный изолированный стенд: фиксированные
ответы вместо провайдера, фиктивные данные и перехваченные запросы. Он показывает
реальные компоненты форм, но не доказывает доступность Gemini или создание записей
на рабочем сервере. Браузерный smoke проверяет четыре перехода, данные ручного
сохранения (перехват без настоящей записи) и компактный экран.
Компонентные тесты дополнительно подтверждают поля окончательных запросов и отсутствие
отправки до ручного сохранения; серверные тесты — подготовку без бизнес-записей и права.
