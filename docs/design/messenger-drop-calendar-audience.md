# Вложения, массовые приглашения и локальные поверхности — 12 октября 2026

## Перетаскивание файлов

Внешние файлы принимаются всей областью основного мессенджера, включая левый список. Во время drag появляется общая спокойная поверхность с названием выбранного чата. Drop добавляет файлы к черновику, не отправляет сообщение и не заменяет текст. Повторная ссылка на тот же объект File не дублируется, но разные файлы с одинаковыми метаданными сохраняются; выбранные кнопкой вложения также добавляются, а не затирают прежние.

Перестановка закреплённых чатов и перенос текста не включают файловый режим. Переходы между вложенными элементами не скрывают подсказку. Выход, Escape, blur и dragend её сбрасывают. Файлы, отпущенные за пределами мессенджера, не открывают новую страницу.

При запрете отправки/вложений, редактировании, записи голоса, серверной операции или открытом окне чата приём заблокирован. Папки не обходятся рекурсивно: показывается просьба выбрать файлы или архив. Размер проверяется общим preflight загрузки до добавления всей пачки; ошибка не удаляет прежние файлы и текст. Серверные проверки вложений сохранены. Новые вложения загружаются прежним механизмом только после явной отправки.

Переход ограничен opacity и общей длительностью micro; нет кадрового обновления React, blur или циклического движения. Reduced motion и forced colors имеют отдельное неподвижное состояние. Кнопка вложения остаётся доступной альтернативой.

## Пригласить всех на мероприятие

В создании и редактировании календарного события доступны три команды: «Все ЦА», «Все регионы», «ЦА и регионы». Они видны только при серверном `canInviteCalendarAudience`. Capability учитывает право создания в календаре и роли admin/superadmin либо должность председателя/заместителя председателя. Варианты узбекского апострофа нормализуются; обычный manager сам по себе не получает массовую команду. Полномочия председателя в других модулях не расширяются.

Команда задаёт `audienceScope`, а не ограниченный список из загруженного клиентом справочника. API заново выбирает всех активных сотрудников на момент сохранения, учитывает региональных предков отдела и блокирует выбранные строки сотрудников. Сотрудник без отдела относится к ЦА. В запросе команды список `attendeeIds` пустой; прежнее ограничение 100 явных ID не усекает серверную аудиторию. Неактивные сотрудники исключены. Организатор включается один раз.

Выбор отдельного сотрудника после команды возвращает явный список без `audienceScope`. Переключение просмотра ЦА/регионов не меняет уже выбранную аудиторию. Существующий запрет пересечений по времени сохранён: занятых не исключаем молча, API отклоняет конфликт с причиной, форма и выбор остаются для исправления. Существующие приглашения и адресная доставка уведомлений используются без нового канала; организатор не уведомляется о собственном приглашении. Личные настройки доставки/звука не обходятся.

Сначала обновляется API, затем web/desktop. Новая миграция не нужна. Старый API не возвращает capability, поэтому новый клиент не показывает массовые команды и не отправляет неподдерживаемый флаг. Новое API продолжает принимать старые запросы с отдельными ID. Обычные права создания/редактирования события не меняются.

## Отступы и непрозрачные фоны

Первая колонка subgrid отметок команды стала intrinsic `max-content`: она учитывает аватар 36 px и боковой отступ строки, оставляя реальные 12 px до имени. Все статусы/графики сохраняют общие колонки. Это не зависит от дополнительного слоя разделения поверхностей, откат которого находится в отдельном PR.

Сводная плашка команды и вторичные кнопки синих шапок используют сплошной близкий к прежнему navy/teal. Hover и disabled тоже непрозрачны; белые основные действия не меняются. Рисунок шапки больше не просвечивает через эти элементы. Общий canvas, заливки списков и другие материалы не перекрашиваются.

## Проверка и границы

- Полный desktop suite: 880 тестов прошли, 1 пропущен; 127 файлов.
- Целевые сценарии: whole-target/nested drag, отмена, сохранение черновика, append/dedup, oversized batch, папка, запрет прав, busy/edit; аудитории/вложенные регионы, неактивные сотрудники, 130 сотрудников, сохранение отказа, возврат к ручному выбору.
- Добавлены Python-тесты роли/должности, серверного scope и защищённая PostgreSQL-проверка уведомлений, конфликтов и более 100 сотрудников. PG-сценарий принимает только отдельную базу `yuksalish_test*` и откатывает тестовые записи. Локально pytest недоступен; результат этих сценариев следует сверять с CI, а не считать пройденным по UI-моку.
- На localhost с синтетическими данными измерены gap 12 px при 1024/640, равные кнопки календаря и отсутствие переполнения при 640/320. Проверены общая drop-поверхность и тестовый файл в черновике без отправки. Background disabled-кнопки — непрозрачный RGB, opacity 1.
- Установленный Electron, перетаскивание из Windows Explorer и настоящий сервер этим браузерным стендом не сертифицированы; рабочие события, чаты и уведомления не создавались. Сервер и установленные клиенты не обновлялись.

QA: `page-canvas.html` содержит явные кнопки симуляции нативных dragenter/drop/dragend с файлом только в памяти и календарь с capability; `profile-avatars.html` — отдельный стенд отметок. API-запись в этих сценариях отключена.

Отсечение папок выполняется только во время drop; контракт метода описан в [MDN](https://developer.mozilla.org/en-US/docs/Web/API/DataTransferItem/webkitGetAsEntry).
