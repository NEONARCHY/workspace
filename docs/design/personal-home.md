# Персональная «Главная»

«Главная» — стартовый хаб каждого сотрудника, не административный обзор команды.
Каждая новая авторизация, восстановление сессии и перезапуск открывают этот раздел.
Прежний раздел в localStorage/sessionStorage не восстанавливается. Сохранённые порядок
меню, архивы и закрепления чатов остаются без изменений. В старый порядок меню
«Главная» добавляется первой; API принимает полный прежний порядок при постепенном обновлении клиентов.

## Данные и переходы

- Фокус: задачи исполнителя/соисполнителя, задачи автора на проверке, сроки управляемых
  или ответственных проектов, ближайшие личные поездки. Наблюдение не означает исполнение.
  Переданный на проверку результат не превращается в просроченное действие исполнителя.
- Уведомления: персональная серверная очередь, сначала требующие решения, потом
  непрочитанные. Завершённые сигналы и устаревшие напоминания Hisobot исключаются.
  Открытие сохраняет существующее подтверждение прочтения и объектные права.
- Мессенджер: только активные неархивные чаты, где сотрудник участник. Открывается
  соответствующая переписка, а не случайный чат.
- Мой отдел: точный departmentId из организационной структуры, серверный счётчик,
  карточки действующих коллег с открытием профиля и раскрытием полного списка.
- Письма: только responsibleUserId в Referent; ЭДО запрашивается с personal=true,
  сервер сужает область до личных назначений до пагинации. Клиент показывает
  строки лишь при visibility=assigned: краткий список ЭДО не содержит назначений,
  поэтому повторного фильтра по employee_id нет. Более широкая либо неподтверждённая
  область не отображается как личная переписка. ФИО не используются для угадывания
  адресата. Превью показывает до трёх последних записей каждого источника.
  Referent открывает входящий реестр с выделением записи; ЭДО — конкретную карточку.
  Кнопка полного реестра сохраняет обычные права раздела (у администратора он может
  быть шире личной главной). Ошибка интеграции, включая 503, имеет повторение;
  загрузка не выдаётся за пустой список. Просрочка отмечается только при
  подтверждённом часовом поясе ЭДО; состояние интеграции не называется разработкой.
- Эффективность: существующая личная методика EFF-2, месяц Asia/Tashkent,
  реальные исторические точки, разрывы при отсутствии данных, пояснение малой/неполной выборки.
  Это соблюдение сроков, не рейтинг ценности человека и не основание кадровых решений.
- Награды: личный профиль, полученные награды коллег и только разблокированные
  системные достижения. Автор награды открывается через профиль.
- Встречи: личные мероприятия и неотклонённые приглашения календаря, запланированные
  Zoom с участием сотрудника. Неготовая интеграция звонков не выдаётся за работающую.
- Лента: реальные публикации, закреплённые первыми, переход к оригиналу.
- Реакции: GET /api/v1/home/reactions считает отклики коллег на сообщения текущего
  сотрудника на сервере, независимо от объёма загруженной переписки. Собственные
  реакции не учитываются. Удалённые сообщения/чаты, отозванное членство и невидимая
  история исключены, включая администраторов. При запрете Messenger содержимое не читается.

Источник каждого блока сохраняет свои модульные и объектные проверки. Нет синтетических
процентов, графиков или демо-контента в рабочем приложении. При ошибке блока доступно
повторение, остальные блоки продолжают работать. Запоздавший ответ прежней сессии
не отображается в новом аккаунте.

## Сетка и приоритет

Две равные колонки, одинаковые внутренние отступы 20px и радиусы 22px.
Корень прозрачен: фон приложения не меняется, стеклянная рамка не возвращается.
Существующий внешний правый отступ единственный. При узком контейнере/масштабировании —
одна колонка. Длинные имена и тексты не расширяют страницу.

Первичная раскладка зависит от срочности: просрочка, проверка результата, важное
уведомление, непрочитанный чат, ближайшая встреча. Фоновое обновление не меняет
порядок под курсором. При изменении приоритетов появляется «Обновить фокус дня»;
после принятия блоки переставляются, порядок DOM совпадает с визуальным.
Анимация только на входе/явном перестроении, transform/opacity 180ms,
без циклического движения, масштабирования текста или изменения высоты по кадрам.
Reduced motion, forced colors, клавиатурный фокус и видимые состояния загрузки соблюдаются.

## Проверка

personal-home.test.ts, PersonalHomeView.test.tsx, App.test.tsx и
tests/python/test_personal_home.py покрывают границы личности/прав, приоритеты,
смену аккаунта, навигацию и серверную агрегацию. qa/personal-home.html — только
изолированные тестовые данные; никаких писем, сообщений или наград на сервер не отправляет.

API с маршрутом home/reactions разворачивается до нового клиента. Новая миграция БД
для «Главной» не нужна; миграции включённых PR применяются в прежнем порядке.
