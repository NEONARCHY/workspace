# Hisobot cutover checklist

## До окна

- [ ] Назначены владелец, оператор, наблюдатель и человек с правом rollback.
- [ ] Проверен restore PostgreSQL и MinIO на отдельном контуре.
- [ ] Утверждены mapping version и допустимые quarantine cases.
- [ ] Пользователи предупреждены об окне недоступности.

## Снимок

- [ ] Telegram polling и старый scheduler остановлены.
- [ ] Процессы действительно завершены.
- [ ] Скопированы SQLite, `-wal`/`-shm` при их наличии, archive и config.
- [ ] `PRAGMA integrity_check = ok`.
- [ ] Создан и независимо проверен SHA-256 manifest.
- [ ] Зафиксировано точное время snapshot.

## Импорт

- [ ] Read-only inspector не выявил неизвестного изменения схемы.
- [ ] Dry-run counts и anomalies приняты владельцем.
- [ ] Apply run имеет уникальный fingerprint и mapping version.
- [ ] Все фазы завершены или строки явно quarantined.
- [ ] Старые delivery/reminder states не создали активных заданий.

## Проверка и ввод

- [ ] Counts сходятся по каждой таблице.
- [ ] Каждый файл финального archive, включая несвязанные legacy DOCX, зарегистрирован и имеет совпадающий hash в PostgreSQL и MinIO.
- [ ] Выборка отчётов, отпусков, missing lists и PDF принята владельцем.
- [ ] Новая система открыта, старый бот переведён read-only.
- [ ] Метрики и журнал ошибок наблюдаются в согласованное окно.

## Rollback

- [ ] Триггер rollback определён до запуска.
- [ ] Запуск помечается `rolled_back`, удаляются только его target rows.
- [ ] Старый polling возобновляется с исходного неизменённого snapshot.
- [ ] Причина и дальнейшее решение зафиксированы.
