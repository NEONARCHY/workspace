# AI Referent: общие согласующие Workspace и Exat

## Что входит в обновление

В Workspace появилась вкладка **AI Referent → Согласующие**, доступная только
администраторам и суперадминистраторам. В GUI Exat адаптер добавляет кнопку
**Workspace · согласующие и Telegram**. Оба редактора сохраняют одну конфигурацию
через API Workspace; отдельный локальный список в подключённом режиме не редактируется.

| Постоянная роль маршрута | Первоначальный логин для выбора |
| --- | --- |
| Аскар | `askar_mamatxanov` |
| Бобур — финальный согласующий | `bobur_bekmurodov` |
| Умид | `umid_rajabov` |
| Давронбек | `davronbek_lyutfiddinov` |

В БД привязка хранится по UUID аккаунта, а логин используется для его выбора.
Переименование должности или логина не переназначает роль другому человеку.
Первоначальные логины — подсказки, а не автоматическая выдача полномочий. После
миграции администратор должен подтвердить аккаунты и включить назначения.
Telegram ID — положительный числовой ID личного аккаунта, не `@username`, не ID группы.
Без Telegram ID роль работает только в Workspace. Один аккаунт/ID нельзя назначить
двум ролям одновременно. Общие запреты доступа к модулю и блокировка аккаунта
имеют приоритет над назначением.

**Этот документ описывает первоначальный этап конфигурации (миграция 46).**
Для общего цикла писем, файлов и уведомлений с миграцией 48 следуйте
[новому runbook совместной работы](ai-referent-shared-workflow.md).
Адаптер этапа 46 сам по себе не переводит
исходящую SQLite-базу робота на общий workflow API, не обеспечивает общий цикл
решений/уведомлений по письму и не загружает архивные файловые пакеты. Для этих
сценариев нужен следующий этап. Уже отправленные письма этим адаптером не удаляются
и не импортируются.

## Бахтиёру: сервер и Workspace

1. Сделать обычную резервную копию PostgreSQL.
2. Обновить сервер до версии с миграцией `0046_ai_referent_reviewers` и выполнить
   `alembic -c apps/api/alembic.ini upgrade head` из корня репозитория в окружении API,
   согласно действующему runbook сервера.
   Новый API и desktop запускать после миграции.
3. Проверить наличие `YUKSALISH_AI_REFERENT_AGENT_TOKEN` в серверной конфигурации.
   Это отдельный случайный ключ агента, **не токен Telegram-бота**. Использовать тот же
   ключ, который настроен для входящего bridge; не публиковать его в Git или чатах.
4. Перезапустить API с обновлённым кодом. Обновить web-сборку/desktop обычным способом.
5. Под администратором открыть **AI Referent → Согласующие**, выбрать четыре реальные
   учётные записи, ввести проверенные Telegram ID, включить нужные роли и сохранить.
   Пользователь Telegram должен предварительно открыть бота и нажать «Старт».

Рабочий сервер и Docker не меняются при подготовке этого кода. Установка EXE и
применение миграции — отдельные действия; обычный Git push их не выполняет.

## На ПК референта: установка в существующую папку Exat

Данные, журналы и архивы остаются на месте. Перед первым подключением сохранить
резервную копию SQLite Exat; обновление исходников устанавливать при остановленном
боте/GUI, без незавершённой отправки.

Из корня обновлённого репозитория Workspace выполнить Python 3.11:

```powershell
python scripts/install_exat_workspace.py --exat-root "C:\path\Exat"
```

Это только проверка: скрипт покажет файлы, которые собирается изменить. Если указана
неподдерживаемая версия исходников, он завершится **до записи**. После проверки:

```powershell
python scripts/install_exat_workspace.py --exat-root "C:\path\Exat" --apply
```

Установщик копирует адаптер из `integrations/exat/workspace_integration`, добавляет
точечные вызовы в три файла Exat и сохраняет оригиналы в
`Exat\.workspace-integration-backups\<время>`. Повторная установка идемпотентна.
Он не запускает робота, Telegram, Docker, отправку письма или миграцию рабочей БД.
Если используется упакованный Exat EXE, после установки адаптера требуется
пересборка EXE стандартным сценарием Exat: правка `src` не меняет старый EXE.

1. Открыть обновлённый GUI Exat → **Workspace · согласующие и Telegram → Подключение**.
2. Указать HTTPS-адрес Workspace (корень или адрес с `/api/v1`), при необходимости
   доверенный корневой PEM-сертификат и ключ агента.
3. Ключ сохраняется в Windows Credential Manager текущего пользователя. В
   `%LOCALAPPDATA%\AIReferent\workspace.json` находятся только адрес, путь сертификата,
   идентификатор агента и исходное сопоставление ролей с прежними Telegram-получателями.
4. GUI автоматически запоминает **явные прежние назначения** из своих полей для
   корректного перевода открытых писем. Если старый получатель неизвестен, бот
   остановит обработку и сообщит об отсутствии сопоставления — он не угадывает роль
   по должности, позиции в списке или похожему имени.
5. Запустить единственный экземпляр бота под тем же Windows-пользователем.
   Workspace должен показать применённую версию в блоке «Применение на ПК референта».

Переменные `YUKSALISH_API_BASE_URL`, `YUKSALISH_WORKSPACE_CA_FILE`,
`YUKSALISH_AI_REFERENT_AGENT_ID`, `YUKSALISH_AI_REFERENT_AGENT_TOKEN`, если заданы,
имеют приоритет над локальными настройками. При изменении адреса через GUI нужно
удалить/обновить конфликтующие переменные окружения. Не отключать проверку TLS.

## Как работает изменение

- В Workspace администратор выбирает аккаунт из активных сотрудников.
- В GUI Exat вводит логин и Telegram ID; для сохранения входит под администратором
  Workspace (с 2FA, если включена). Пароль и административный токен не сохраняются;
  временный сеанс отзывается после операции.
- GUI перечитывает настройки раз в 15 секунд. При конфликте версий ввод остаётся
  на месте; нужно сравнить и сбросить форму к актуальной версии.
- Бот читает конфигурацию перед циклом обработки и перед каждым полученным update.
  Обычно задержка не больше одного long-poll Telegram (около 25–30 секунд), плюс
  время уже запущенной операции. Мгновенная доставка не обещается.
- Бот применяет новую конфигурацию между операциями без принудительного завершения
  процесса. Уже идущая отправка завершается на старой конфигурации; новую операцию
  бот начинает после обновления. Не требуется удалённый shell или kill/restart.
- Открытые решения переводятся на новое назначение. Старые Telegram-кнопки больше
  не дают старому получателю права согласования. Для нового адресата ставится
  повторяемое уведомление; при сбое Telegram оно повторяется. Доставка уведомления
  at-least-once: редкий дубль после сбоя возможен, дублирование решения не требуется.
- История завершённых согласований и отправок остаётся неизменной. Переназначение
  фиксируется в аудитах Workspace и Exat.
- Если Workspace недоступен или конфигурация не подтверждена администратором,
  подключённый бот не принимает новые решения по устаревшим правам. Входящий робот
  и сохранённые архивы не отключаются этим адаптером.
- Факсимиле/подпись **не переносится автоматически** от старого сотрудника новому.
  Для нового человека её необходимо отдельно настроить штатным способом Exat.

## Приёмочная проверка перед рабочим использованием

Проверять на отдельном боте/тестовых письмах, а не реальной отправкой:

1. Изменить логин/Telegram ID в Workspace, дождаться обновления GUI и подтверждения бота.
2. Изменить их через GUI с администратором: изменения должны появиться в Workspace.
3. Открыть оба редактора, внести разные изменения и сохранить последовательно:
   второй должен получить конфликт, не перезаписав первое изменение.
4. Создать тестовое открытое согласование, переназначить роль; проверить отказ старой
   кнопки, уведомление нового адресата и сохранность прошлой истории.
5. Отключить роль/заблокировать аккаунт, проверить отказ; включить обратно и проверить
   восстановление без перезапуска бота.
6. Отключить сеть Workspace: бот не должен принимать решение по старой конфигурации.

## Откат

Остановить бот и GUI, восстановить три исходника из резервной копии установщика
(список и SHA-256 оригиналов в `manifest.json`). Адаптер можно оставить неиспользуемым.
Если он уже работал и переназначал письма, откат одних исходников **не откатывает
данные**: сначала согласовать назначения либо восстановить проверенную резервную
копию SQLite. Не откатывать рабочую PostgreSQL-миграцию вслепую после новых записей.
