# AI Referent: запуск общего цикла Workspace + Telegram + Exat

## Что меняется

PostgreSQL Workspace хранит актуальное письмо, согласующих, решения, номер и очередь
действий. Workspace и Telegram обращаются к одному API. ПК референта готовит PDF,
накладывает настроенную подпись и выполняет внешнюю отправку штатными средствами Exat.
Его SQLite остаётся техническим журналом робота, а не второй независимой очередью решений.

Входящий робот работает как прежде. Адаптер копирует записи, пакеты файлов и журналы
в Workspace. **Ничего не переносит и не удаляет из существующего архива.** Присылать
разработчику архивную базу для обычного подключения не требуется.

Адресная книга для нового исходящего письма берётся из того же каталога Exat, что
использует Telegram-бот. Обновлённый агент передаёт серверу только названия,
категории, адреса и каналы получателей; исходный каталог и SQLite остаются на ПК
референта. В Workspace доступен компактный поиск и ручной ввод, если адресата
ещё нет в справочнике. После обновления сервера нужна миграция
`0050_ai_referent_recipients` и обновление/пересборка Exat на ПК референта.
Первый запуск обновлённого агента загружает каталог, дальнейшие изменения
передаются при очередной синхронизации. До появления первой копии ручной ввод
продолжает работать. Не заменяйте прежнюю адресную книгу тестовым файлом.

«Пакет документов» — папка внутри интерфейса: файлы можно скачать отдельно или ZIP.
Это не открытие диска C: другого компьютера через сеть. Доступ к серверным копиям
сохраняется, когда ПК референта выключен. Новые входящие/версии появятся после его включения.
Один файл — до 200 МБ при синхронизации пакетов, ZIP — до 200 МБ несжатых данных;
более крупные пакеты скачиваются по файлам. Telegram принимает загрузку до 20 МБ.

## Бахтиёру — что сделать на сервере

Одного доступного API недостаточно: нужны постоянные PostgreSQL и MinIO, обычные
Redis/worker/scheduler проекта и HTTPS, доступный с ПК референта. Telegram обслуживает
сам ПК референта; токен бота на сервер Workspace передавать не нужно.

1. Согласовать короткое окно обновления. Остановить бот Exat, завершить старые
   незавершённые согласования/отправки. Проверить внешний журнал «Отправленные».
2. Сделать проверенную резервную копию PostgreSQL **и MinIO**, сохранить серверный
   env-файл отдельно. На ПК референта сохранить SQLite, папки писем, журналы,
   настройки/подписи и `%LOCALAPPDATA%\AIReferent` (если уже существует).
3. После review и зелёного CI объединить PR и получить общую версию:

   ```powershell
   git switch main
   git pull --ff-only origin main
   ```

4. В **существующем** серверном env-файле установить
   `YUKSALISH_AI_REFERENT_AGENT_TOKEN`: отдельный случайный секрет не короче 32 байт.
   Это **не токен Telegram** и не пароль администратора. Если входящий bridge уже
   использует ключ агента — сохранить тот же ключ. Не присылать его в чат/коммит.
   TLS проверяется: для LAN передать на ПК референта доверенный корневой PEM.
5. Пересобрать сервер обычным способом текущей установки, сохранив все volumes.
   В `infrastructure/compose.yaml` API сам выполняет `alembic ... upgrade head`
   перед запуском. Для общего цикла обязательна миграция **0048_ai_referent_shared**;
   поиск адресатов требует также **0050_ai_referent_recipients**.
   Если API запускается не через этот Compose, применить её отдельно из окружения API:

   ```powershell
   alembic -c apps/api/alembic.ini upgrade head
   ```

   Пример **для установки с `.env.production` и базовым Compose**:

   ```powershell
   $env:YUKSALISH_ENV_FILE = "../.env.production"
   docker compose --env-file .env.production -f infrastructure/compose.yaml up -d --build api worker scheduler
   docker compose --env-file .env.production -f infrastructure/compose.yaml exec api alembic -c apps/api/alembic.ini current
   ```

   При LAN/web-установке использовать её существующий `.env.lan` и **все прежние
   Compose overrides** из [LAN runbook](lan-server-transfer.md), а не заменять их
   примером выше. Не выполнять `down -v`, не пересоздавать БД и не менять LAN-адрес вслепую.
6. Обновить web-сборку и desktop-клиенты обычным способом. Push не обновляет EXE.
7. В **AI Referent → Согласующие** подтвердить аккаунты Аскара, Бобура, Умида,
   Давронбека и их Telegram ID. Подробности: [общие настройки](ai-referent-reviewers.md).
   Для оператора-референта выдать право **администрирования AI Referent** через
   существующий конструктор прав модуля: оно нужно для окончательной отправки
   и ручной сверки неизвестного результата. Не обязательно делать человека
   глобальным администратором. Настройки самих согласующих меняют только админы.

## На ПК референта — установка и активация

Установить исходники при закрытых GUI и боте. Из обновлённой папки Workspace:

```powershell
python scripts/install_exat_workspace.py --exat-root "C:\путь\Exat"
python scripts/install_exat_workspace.py --exat-root "C:\путь\Exat" --apply
```

Первая команда ничего не меняет. Вторая создаёт резервные копии изменённых исходников
в `Exat\.workspace-integration-backups`. Если версия Exat неизвестна, установка
останавливается до записи. Для упакованного EXE потребуется штатная пересборка Exat.

1. Открыть GUI → **Workspace · согласующие и Telegram → Подключение**. Сохранить
   HTTPS-адрес, доверенный сертификат и ключ агента Бахтиёра. Ключ хранится в Windows
   Credential Manager. Закрыть GUI/бот перед следующей командой.
2. Проверить корректные адресную книгу, Word/PDF-подготовку, факсимиле выбранных
   людей и действующий вход в E-XAT/Webmail. Новое назначение **не создаёт подпись**.
3. Из папки Exat, тем же Python/Windows-пользователем, которым запускается робот:

   ```powershell
   python -m src.workspace_integration.setup --enable-shared-workflow
   ```

   Команда откажет, если остались старые незавершённые письма. Сначала копирует
   архивные реестры/файлы/журналы, сверяет занятые номера, затем разрешает общую
   нумерацию. При большом архиве это не мгновенно. Повтор продолжает безопасно:
   записи имеют стабильные ID, файлы — контрольные суммы. Ошибку отсутствующего
   файла/неверного пути нужно устранить, а не удалять запись ради запуска.
4. Запустить **один** экземпляр Telegram-бота обычной кнопкой GUI Exat.
   Состояние выполнения хранится в `%LOCALAPPDATA%\AIReferent\shared-state.sqlite`.
   Не удалять этот файл для «сброса зависания»: он защищает от повторной отправки.
5. Рабочий сеанс Windows должен быть доступен для GUI-автоматизации Exat. Не
   запускать её как невидимую Windows-службу/в заблокированном сеансе без проверки.
   Автозапуск — после входа того же пользователя, после приёмочного теста.
6. Старый входящий bridge можно остановить **после** проверки общего адаптера:
   он уже копирует входящие, пакеты и Excel примерно раз в минуту. Сам входящий
   робот не останавливать — он продолжает регистрацию. GUI конфигурации обновляется
   примерно раз в 15 секунд; реестры Workspace — раз в 15 секунд; доставка Telegram
   зависит от long-poll и сети. Мгновенная синхронизация без сети не обещается.

Не включать одновременно старый автономный бот на другом ПК. Переменная
`YUKSALISH_AI_REFERENT_SHARED_WORKFLOW`, если задана, переопределяет локальную настройку.
Старые локальные кнопки согласования/отправки в общем режиме защищены от обхода API.

## Для сотрудников

- Администратор указывает личный Telegram ID сотрудника и выдаёт доступ к AI Referent
  в разделе «Доступ к Telegram-ботам». После сохранения доступ действует без кода
  `/link`; сотруднику достаточно открыть бота и нажать «Старт», чтобы получать сообщения.
- Создать черновик можно из Workspace или `/new` в Telegram. Основной файл — DOCX;
  остальные файлы добавляются отдельно. Выбрать первого и, при необходимости,
  второго согласующего. Каналы внешней отправки — E-XAT и Webmail, не новый EDO-процесс.
- `/history` — актуальные письма, `/archive` — ранее отправленные в Exat.
  При большом реестре доступны страницы. Уведомление всегда открывает актуальную
  серверную запись; старая кнопка не отменяет проверки версии и полномочий.
- Согласование → подготовка подписанного PDF → финальное решение Бобура, если
  он финальный согласующий → проверка и отправка референтом. PDF доступен в пакете.
  Все решения, возврат с комментарием и отправка доступны с обоих клиентов по правам.
- При смене согласующего открытая заявка переходит новому аккаунту. Прежнее решение
  остаётся в аудите. Уже выполняемую внешнюю операцию нельзя безопасно «перезапустить»:
  новые назначения применяются к последующим решениям без удалённого kill процесса.

## Неизвестный результат — не нажимать повтор вслепую

Если робот/сеть пропали после возможного нажатия «Отправить», сервер показывает
«Результат отправки неизвестен». Повторная отправка автоматически не запускается.
Референт проверяет внешние «Отправленные», адресата и номер, затем выбирает
«Подтвердить отправку» либо «Подтвердить, что не отправлено» с обязательным основанием.
Второе действие лишь возвращает к проверке: для новой отправки нужно явное подтверждение.
Не выбирать его только потому, что нет ответа API. Внешняя почта не предоставляет
общую транзакцию с PostgreSQL; абсолютное exactly-once при аварии не обещается.
Уведомления повторяются при сбоях; редкий дубль уведомления возможен, решение не дублируется.

## Приёмка перед реальными письмами

На отдельном тестовом контуре/тестовом адресате с разрешением владельца:

1. Сверить число входящих/архивных исходящих, несколько старых номеров, открыть
   письмо с приложениями и Excel. Убедиться, что исходные файлы остались на ПК.
2. Создать письмо в Workspace, вернуть с комментарием в Telegram; автор видит его
   в обоих клиентах. Заменить DOCX, повторить согласование. Проверить обе ступени.
3. Проверить пакет подписанного PDF до внешней отправки. Одна разрешённая тестовая
   отправка должна дать тот же статус и номер в Workspace, Telegram и журнале Exat.
4. Проверить старую кнопку, неучастника, отключённый аккаунт и смену согласующего.
5. Проверить потерю сети до отправки и аварийный сценарий на поддельном транспортном
   адаптере: неизвестный результат требует ручной сверки, не повторного клика.
6. Только после этого включить автозапуск и рабочую отправку.

Подготовка кода и CI не заменяют проверку Word, факсимиле и внешних сайтов на ПК
референта. В рамках разработки сервер Бахтиёра, Docker и рабочая БД не изменяются.

## Откат

Остановить общий бот, проверить незавершённые/неизвестные отправки. Сохранить обе
БД, MinIO и локальные квитанции выполнения. Не включать старый автономный бот, пока
в общем контуре есть активные письма: это разделит очередь и нумерацию.
Согласовать ручную сверку, затем при необходимости восстановить исходники из
резервной копии установщика. Миграцию 48 нельзя откатывать поверх новых активных
статусов; восстановление данных — отдельная операция из согласованной резервной копии.
