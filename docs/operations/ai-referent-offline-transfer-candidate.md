# AI Referent: тестовый перенос автономной сборки

Этот комплект **не разрешён для рабочего включения**. Флаг
`YUKSALISH_AI_REFERENT_OFFLINE_AUTHORITY_ENABLED` остаётся выключенным до
совместного испытания на ПК референта: отключение Workspace до/после реального
клика E-XAT и Webmail, перезапуск бота, сверка сомнительной доставки и повторное
подключение. Письма, подписи и пароли для такого испытания должны быть тестовыми.

## Что находится в комплекте

- Исходники Exat с обновлённым адаптером и `dist/YuksalishAIReferent.exe`.
- Конфигурация, `.env`, подписи, адресные файлы, SQLite и рабочие архивы **не входят**.
- EXE не содержит этих файлов внутри и не стартует без внешних пяти YAML-файлов
  `config` рядом с EXE или уровнем выше (обычный путь `Exat/dist/../config`).
- Папка данных `C:\EXAT_ROBOT_MALUMOTLAR` остаётся на ПК референта без замены.

## Перед ручным тестом

1. Бахтиёр сохраняет резервные копии PostgreSQL и MinIO. На тестовом сервере
   устанавливает коммит Workspace из комплекта, применяет Alembic до `head`,
   пересобирает API/worker/desktop из одного коммита. Миграция `0067` добавляет
   администраторскую адресную книгу. Не включать офлайн-флаг на рабочем сервере.
2. На ПК референта остановить **все** экземпляры бота/EXE. Скопировать отдельно
   всю текущую папку Exat, `config`, `.env`, папку подписей и
   `C:\EXAT_ROBOT_MALUMOTLAR`. Проверить, что резервные копии открываются.
3. На **тестовой копии** папки Exat развернуть ZIP поверх старых исходников и EXE,
   не удаляя и не заменяя локальные `config`, `.env`, подписи, адресные файлы и
   папку данных. Если любой из пяти YAML отсутствует, запуск остановится —
   восстановить именно конфигурацию ПК референта, не копировать чужую.
4. Сверить адрес сервера, доверенный сертификат, ключ агента и права доступа
   локально, не присылая секреты в чат. Запустить только один тестовый экземпляр.
5. Пройти все этапы с тестовым DOCX и тестовым получателем. До испытания внешней
   отправки убедиться, что тестовый канал не доставит настоящее письмо.

После успешного теста всё равно нужен отдельный согласованный выпуск: сервер и
ПК референта должны работать с совместимыми версиями. Git-коммит или копирование
ZIP сами по себе не обновляют запущенный сервер и не мигрируют базу.

При отказе не переключать сервер и бота между старой и новой версиями поверх
одной рабочей базы. Сначала остановить процессы и сохранить диагностические
журналы; восстановление делать по проверенным резервным копиям и после сверки
исходящих писем.
