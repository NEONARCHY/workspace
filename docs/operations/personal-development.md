# Личный локальный Workspace для разработки

Это настоящий web-клиент и API из текущей рабочей папки, а не QA-макет.
Он не зависит от офисного сервера и не требует PR/merge для проверки изменений.
Доступен только на этом ПК: **https://localhost:5173**.

## Запуск и остановка

Нужны Docker Desktop (запущенный engine), Node.js и зависимости проекта (`pnpm install --frozen-lockfile`).
Из корня той рабочей папки, функции которой вы хотите тестировать:

```powershell
pnpm dev:local
pnpm dev:local:status
pnpm dev:local:stop
```

Первый запуск собирает образ API, применяет миграции и создаёт пример рабочих данных.
Последующие запуски сохраняют тестовые задачи, переписку и загруженные файлы.
Запуск фоновый, без открытого терминала. Для запуска с видимым журналом:
`node scripts/dev/local-workspace.mjs start`.
Ctrl+C останавливает frontend; `dev:local:stop` также останавливает личные контейнеры.
Для запуска двойным щелчком есть `scripts/dev/start-local.cmd` (дожидается готовности
и открывает браузер) и `scripts/dev/stop-local.cmd`. Ярлык на них может быть размещён
на рабочем столе; он должен указывать именно на выбранную рабочую папку.

Вход: `malika` (администратор, Малика Нурова). Также есть `aziza`, `baxtiyor`, `dilshod`.
Случайный тестовый пароль хранится в поле `demoPassword` файла
`%LOCALAPPDATA%\Yuksalish Workspace Dev\config.json`.
Не публикуйте этот файл: в нём отдельные личные ключи и пароли.
Журнал запуска — `server.log` в той же папке.

Интерфейс обновляется через Vite HMR, API — через Uvicorn reload.
После изменения зависимостей, миграций или параметров `config.json` остановите и запустите среду повторно.
Нельзя одновременно обслуживать один адрес из двух checkout: остановите предыдущий перед переключением.
Проверка настоящих HTTPS-запросов: `pnpm check:local-dev`. Она работает только с
личным deployment, создаёт одну помеченную тестовую задачу с текстовым вложением,
проверяет вход, CSRF, cookies, refresh и сохранность этой записи. Повторный запуск
читает ту же запись, а не создаёт дубликаты.

## HTTPS

При первом запуске создаётся собственный сертификат только для localhost/127.0.0.1,
действующий год. HTTPS, Secure cookies, проверки Origin и CSRF не отключаются.
Без доверия сертификату браузер показывает предупреждение. Добавление сертификата
в Windows выполняется только после согласия владельца, в хранилище текущего пользователя:

```powershell
Import-Certificate -FilePath "$env:LOCALAPPDATA\Yuksalish Workspace Dev\tls\localhost.crt" -CertStoreLocation Cert:\CurrentUser\Root
```

Доверяйте только сертификату, созданному этим локальным запуском. После автоматического
перевыпуска при истечении срока потребуется снова подтвердить доверие.

## Изоляция и интеграции

- Docker project: `yuksalish-personal-dev`, отдельные сети и именованные volumes.
- База `yuksalish_personal_dev`; PostgreSQL, Redis и MinIO вообще не опубликованы на хост.
- API опубликован только на `127.0.0.1:18080`, frontend на loopback 5173.
- Секреты и endpoint основного сервера не копируются и не наследуются из `.env` или shell.
- Не используются production/test-базы, аккаунты реальных сотрудников или робот Exat.
- Gemini, Zoom и мосты по умолчанию выключены. Для настоящего ИИ добавьте **свой**
  Gemini key в `geminiApiKey` личного `config.json` и перезапустите среду.
  Запросы с этим ключом могут тарифицироваться Google; без него ответ ИИ не проверяется.
- Автозаполнение примерами выполняется только при пустой базе; перезапуск не восстанавливает
  удалённые вами тестовые записи и не сбрасывает пароли.
- Остановка не удаляет volumes. Launcher не содержит команды очистки базы или `down -v`.

Это среда разработки, не резервная копия и не сервер для внешних пользователей.
Незакоммиченные изменения остаются в выбранной рабочей папке. PR нужен только когда
вы решите перенести готовую функцию в общую версию.
