# AI Referent: проверка DOCX и итогового PDF — обновление 0055

## Как работает цикл

1. Автор загружает основной DOCX. До любых подписей и нумерации робот на ПК
   референта экспортирует его через Word и проверяет безопасное размещение настроенных
   факсимиле. Это техническая проверка макета, не проверка смысла или орфографии.
   Временная подсказка исчезает после результата. Неудача блокирует согласование и
   предлагает обратиться в IT. Выключенный ПК оставляет проверку в ожидании.
   Очередь этих проверок работает отдельно от стартовой сверки архива: если уже
   назначенный робот не может завершить сверку, DOCX всё равно проверяется. Сверка
   по-прежнему обязательна перед нумерацией и реальной отправкой.
   Для известных подписантов Exat сопоставляет полное ФИО из Workspace с именем
   настроенного факсимиле по имени **и** фамилии, независимо от порядка и отчества.
   Неизвестного человека или одно совпавшее слово робот не подменяет чужой подписью;
   требование безопасной свободной области в PDF остаётся обязательным. В Telegram
   ожидание и результат обновляются в одном служебном сообщении без ручной кнопки
   проверки состояния; результат приходит автоматически, пока робот работает.
2. В Telegram следующий шаг — приложения; затем адресат, согласующий и подтверждение.
   «Назад» доступен на каждом шаге черновика. Для Бобура предварительный согласующий
   обязателен. Система также проверит пригодность DOCX именно для конечного подписанта.
3. Workspace позволяет заполнить поля одной формой, включая drag-and-drop файлов.
   До «Сохранить черновик» поля локальны; проверка DOCX уже выполняется на серверной
   очереди, но письмо ещё не создано. Сохранённый черновик и все последующие состояния
   общие для обоих клиентов. В Telegram черновик сохраняется по шагам.
4. Любой согласующий возвращает письмо с текстом или голосовой записью до 5 минут.
   Автор получает комментарий в обоих клиентах. Запись Workspace в формате WebM
   передаётся Telegram как аудиофайл; Telegram OGG — как голосовое сообщение.
   Автоматическая расшифровка не выполняется. Перед отправкой комментария запись
   можно прослушать/удалить; она не заменяет явное действие возврата.
5. При маршруте через Бобура после его согласия робот сразу готовит номер и подпись.
   Бобур получает только основной итоговый PDF с «Отправить» / «Вернуть на доработку».
   Вложения остаются в пакете и не прикладываются к этому просмотру.
6. «Отправить» подтверждает конкретную версию PDF. Робот открывает отправку по
   выбранному каналу. При включённом GUI-флаге реальной отправки запускается отправка;
   при выключенном письмо остаётся референту для явного решения. После подтверждённой
   доставки автор и участвовавшие согласующие получают итоговый PDF.
7. Возврат итогового PDF снимает его допуск к отправке. Номер сохраняется, исправленный
   DOCX проверяется заново, весь маршрут согласования начинается сначала.
8. При маршруте без Бобура после согласия одного руководителя действует прежний
   выбор автоматической/ручной отправки. «Только подпись» остаётся отдельным режимом
   без адресата и номера; каждая физическая страница проверяется и подписывается отдельно.
9. Администраторская замена на этапе референта остаётся отдельным ранее согласованным
   исключением: без повторного согласования, с сохранением номера и только ручной
   отправкой. Она недоступна обычному автору.

## Удаление и чистый чат

Автор и администратор видят «Удалить письмо из базы» с подтверждением. Без номера
удаляется общая запись; после нумерации сначала робот закрывает подготовленное окно и
удаляет техническую запись локального реестра, затем удаляется общая карточка.
Номер не используется повторно. Отправленное, подписанное завершённое, исполняемое
письмо и неизвестный результат доставки удалять нельзя. Ошибка локального удаления
требует сверки, не запускает новую отправку. Минимальный аудит удаления и резервные
объекты файлов сохраняются: это не обещание физического стирания всех копий/бэкапов.

Бот отслеживает только собственные служебные подсказки/кнопки и их версии, включая
перезапуск. При переходе старые подсказки удаляются. Если Telegram не разрешает
удаление, бот пытается убрать кнопки и отметить завершённый этап. Пользовательские
сообщения, содержательные комментарии, аудио и PDF не удаляются. Уже старые сообщения
прежней версии, которых нет в журнале, массово не очищаются. Редкий дубль уведомления
при потере подтверждения Telegram возможен; повтор бизнес-решения защищён API.

## Порядок установки — Бахтиёр и Темур

1. Согласовать окно; остановить GUI/бот на ПК референта, убедиться, что нет текущей
   внешней отправки. Сделать резервные копии PostgreSQL, MinIO, SQLite робота,
   архивов и `%LOCALAPPDATA%\AIReferent`. Не удалять Docker volumes или журналы.
2. Бахтиёр после объединения PR обновляет `main`, пересобирает API/worker/scheduler
   и web с **текущими LAN env и Compose overrides**. Применяет
   `alembic -c apps/api/alembic.ini upgrade head`, проверяет head
   `0055_ai_referent_preflight`. Подробный порядок сохранён в
   [общем runbook](ai-referent-shared-workflow.md).
3. Миграция закрепляет точный PDF завершённых подготовок. Если старое письмо ждало
   финального решения без PDF, создаётся только задание подготовки, не отправки.
4. Темур ставит новую сборку/адаптер Exat при закрытом роботе. Сохраняет действующие
   настройки подключения, ключ в Credential Manager, SQLite и архивные папки.
   Повторная активация общего режима для уже подключённого ПК не нужна.
   Старый EXE одновременно с новой версией сервера не запускать.
5. Обновить desktop-клиенты, если используется EXE Workspace. Web обновляется на сервере.
6. Запустить ровно один робот. Проверить heartbeat и провести приёмку на разрешённых
   тестовых документах/адресате: хороший и неподходящий DOCX; Back; текст/аудио;
   возврат Бобура после PDF; обе настройки реальной отправки; старые кнопки;
   перезапуск до/после решения; удаление черновика и подготовленного письма.

Тесты разработки используют отдельную PostgreSQL и поддельный транспорт. Они не
заменяют приёмку установленного Word, реальных факсимиле и сайтов E-XAT/Webmail на
ПК референта. Реальная отправка без отдельного разрешения при разработке не выполняется.
Откат БД после появления аудио требует экспорта: downgrade не удаляет записи молча.

## Если сообщение о проверке DOCX не исчезает

На ПК референта проверьте журнал `outgoing_telegram_bot.log` в папке журналов
исходящих писем (по умолчанию
`C:\EXAT_ROBOT_MALUMOTLAR\jurnallar\chiquvchi_xatlar`). Записи
`workspace_preflight_failed` объясняют сбой отдельной очереди проверок;
`workspace_bootstrap_failed` относится к сверке архива и больше не должен сам по
себе блокировать DOCX. Ошибка «Проверка доступна только назначенному ПК» означает,
что агент ещё не назначен через успешную стартовую сверку или запущен другой робот.
Не удаляйте письма и не меняйте серверную БД для устранения ожидания. Если в журнале
нет попыток проверки, убедитесь, что на ПК референта запущен именно обновлённый EXE.
