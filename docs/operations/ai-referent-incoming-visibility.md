# Видимость входящих Workspace без обновления Exat

Изменение относится к серверу Workspace и web/desktop. Исходники, EXE, SQLite,
настройки согласования и синхронизация установленного робота не меняются.

## Установка

1. Сделать обычную резервную копию Workspace и применить новую аддитивную миграцию
   `0077_referent_incoming_access` командой `alembic upgrade head` на выбранном сервере.
   Миграция добавляет личные правила и индекс; не меняет письма и назначения робота.
2. Обновить API и затем web/desktop. Старый клиент не скрывает вкладку, но обновлённый
   API всё равно запрещает доступ. При откате API старый код снова будет считать
   достаточным одно `ai_referent.view`: не откатывать его, рассчитывая сохранить защиту.
3. Под администратором открыть AI Referent → «Видимость писем». Проверить председателя
   и заместителей, а также аккаунты Ботира Мардаева, Саиды Мустафаевой и Аскара
   Маматханова. Обобщённая роль «Руководитель» отдела не раскрывает всю почту.
4. При несовпадении официальных имён или отсутствии писем выбрать сотрудника,
   «Только назначенные Exat» и точные ответственные ID из уже полученной синхронизации.
   Сохранить. Настройка применяется к следующим запросам сразу; открытый клиент
   перепроверяет права и обновляет реестр каждые 15 секунд. Старые скачанные копии
   и уже прочитанную информацию отозвать невозможно.
5. Для исключений доступны «Нет доступа», «Все входящие» и «По умолчанию». Общий
   запрет просмотра модуля имеет приоритет над личной видимостью. Глобальным
   администраторам невозможно закрыть переписку этим редактором.

## Если данные Exat неполные

Действующий контракт уже содержит `responsibleExternalId` и `responsibleDisplayName`.
Этого достаточно без обновления робота. Если установленная версия не передаёт эти
поля либо ID отсутствуют, новые назначения не угадываются по теме, автору или
локальному пути: сотрудник не получает чужие письма. Сначала проверить уже
синхронизированные данные. Если нужен другой формат назначения, запросить актуальную
папку установленного Exat у владельца и отдельно согласовать обновление; не ставить
имеющийся в репозитории адаптер поверх неизвестной рабочей версии.

## Приёмка

- Администратор/суперадминистратор: все входящие и исходящие Workspace, без права
  согласовывать за других или изменять чужой черновик.
- Председатель/назначенные заместители: все входящие.
- Три названных сотрудника: только собственные назначения, включая поиск и счётчики.
- Остальные: вкладки входящих/общих журналов нет; прямой запрос запрещён.
- Чужой пакет/ZIP/отдельный файл недоступен; общий Excel и смешанный архив закрыты
  для ограниченного списка. Явная привязка одного ПК не раскрывает одинаковый ID другого.
- После смены правила запросы учитывают его без перезапуска, устаревший редактор
  получает 409, изменения и администратор записываются в аудит.
- Рабочий офисный сервер обновляется только по отдельному запросу владельца.
