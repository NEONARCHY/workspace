# Проверки Pull Request

CI запускается для каждого PR в main. Новый push отменяет предыдущий запуск
того же PR; параллельные PR друг друга не отменяют.

Перед дорогими заданиями проверяются заметки обновления и правила выбора проверок.
Обязательные статусы сохраняются: python, desktop, secrets. Ошибка или отмена
preflight, релевантного задания или тестового шарда не может дать зелёный статус.

## Какие задания запускаются

| Изменения | Python | Desktop |
| --- | --- | --- |
| apps/api, modules, tests/python, Python-зависимости | Да | Нет |
| apps/desktop, кроме собственной pending-заметки | Нет | Да |
| docs, README.md, AGENTS.md, CONTRIBUTING.md, LICENSE, pending-заметки | Нет | Нет |
| Общие packages, workflow, scripts, инфраструктура, корневые настройки и неизвестные пути | Да | Да |
| Ручной workflow_dispatch или пустой diff | Да | Да |

Смешанные изменения объединяют нужные области. Сравнивается полный diff PR
от merge base, а не только последний коммит. Для переименования учитываются
старый и новый пути. Ошибка чтения diff блокирует CI.

Secrets проверяется на каждом PR независимо от выбранных областей.
Пропуск нерелевантного набора подтверждается обязательным итоговым заданием;
workflow целиком не пропускается, чтобы required checks не оставались Pending.

## Desktop-тесты

Все тестовые файлы сохраняются в запуске. Четыре Windows-шарда выполняют их
по одному процессу на раннер: увеличение параллелизма внутри раннера ранее
вызывало нехватку памяти и нестабильные UI-таймеры.

Явный список в apps/desktop/vitest.node-tests.mts содержит проверки без DOM:
вычисления и контракты исходников/CSS. Они используют Node без jsdom и
Fluent/Tabster setup. Все остальные, в том числе новые тесты, по умолчанию
используют прежнюю UI-среду. Изоляция тестовых файлов остаётся включённой.

Локальные команды из корня:

```powershell
pnpm test:workflow
pnpm --filter @yuksalish/desktop exec vitest run --project node --maxWorkers=1
pnpm --filter @yuksalish/desktop exec vitest run --shard=1/4 --maxWorkers=1
```

Сравнивать ускорение нужно по длительности заданий и фазам Vitest из логов,
учитывая повторные попытки и очередь GitHub. До оптимизации CI #621 для PR #225
занял 12:03; самый долгий renderer-шард — 11:51, из них шаг тестов — 10:32.
